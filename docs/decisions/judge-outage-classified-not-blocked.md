# judge-outage-classified-not-blocked

## Target · 2026-09-03 — A judge outage is CLASSIFIED at the failure site, not guessed at, and reachability is REPORTED

**Context:** A codex account hit a six-day usage lock. devkit ship ran the entire deterministic chain to green, then spawned 8 reviewers that each failed, retried once, and failed again — 16 spawns, every one printing 'codex judge unavailable (1; offline/quota/absent)', and the cascade logging '(transient), retrying once…' for an outage no retry could clear for a week. The evidence was already in hand at the failure site: a quota-locked 'codex exec --json' exits 1 while emitting turn.failed with the cause AND the reset date on stdout, which codexFailure has always parsed — run-judge caught the throw, handed the message builder Node's generic error, and mined that same stdout buffer for token usage one line later without ever asking it what went wrong. An unattended agent following the printed 'devkit ship --resume' remedy burns an attempt per hour against a week-long wall.
**Ruling:** A judge outage is CLASSIFIED at the failure site, not guessed at, and reachability is REPORTED before the chain but never enforced there. classifyJudgeOutage (gate-engine/judge/outage.mts) splits absent / unauthenticated / rate-limited out of the fused offline/quota/absent label using only the provider's own channels — the structured turn.failed event and stderr, never the Node error message, which renders the judge's argv and therefore the staged diff. Every classification is positive-signal-only: an unrecognised failure stays transient. Each kind carries 'permanent', the single input to every retry predicate, replacing the cascade's firstOutage !== 'timeout' test. A ship-time preflight reads codex app-server account/rateLimits/read (non-billed, ~1s, answers while inference is refused) and prints provider, model, window use and reset per ROLE — then continues unconditionally.
**Consequences:**
- Positive: An operator or unattended agent learns the actual cause and the actual wait the first time a judge goes dark, at every gate that spawns one — the review cascade, commit-msg completeness, and decision-alignment alike. A permanent outage costs 8 spawns instead of 16. The fail-closed decision stays at guard-review under GUARD_AI_STRICT, the only point that knows whether judge work remains, so a fully-cached converging re-ship still succeeds against a dark provider exactly as ship-gates-converge-not-restart guarantees.
- Negative: Two provider-text matchers and a reset-time parser now depend on undocumented CLI wording, and codex app-server is marked [experimental] upstream; all three can silently stop matching after a provider release. That cost is bounded by construction — every one degrades to today's behaviour ('transient', or silence) rather than to a wrong answer — but it buys accuracy with maintenance rather than with certainty. The preflight also declines the faster feedback a hard block would give: a genuinely doomed ship still pays the full deterministic chain before failing.
**Vision-fit:** n/a — internal tooling. Serves devkit's own W-3 promise that a consumer's ship reports what actually happened rather than a plausible-sounding collapse of three unrelated causes.
**Researched:** codex-cli 0.152.0 app-server account/rateLimits/read called live on a locked account (1.09s, usedPercent 100, resetsAt 2026-09-07); openai/codex codex-rs/app-server/README.md; peer consumers steipete/CodexBar and Git-on-my-level/codex-autorunner both read limits from this RPC and use CODEX_HOME JSONL only for token cost; anthropics/claude-code#40395 (open) confirms the claude family has no equivalent query.
**Rejected:** A BLOCKING preflight, which the originating report asked for: run-review.mts returns 0 with zero judge spawns when every reviewer is a cache hit, so a pre-chain block newly fails converging re-ships that succeed today, and the bypass env it would need becomes the routine path (gate-opt-out-is-visible-and-detectable). A live 'codex exec' probe: it costs a real inference call on every ship drawn from the pool it protects — at 99% used the probe is the call that trips the limit. Scraping ~/.codex rollout JSONL: measured, rate_limit_reached_type was null in all 236 local rollouts and no file existed for the locked day. Runtime cross-family fallback: still rejected per review-gate-in-chain — the preflight NAMES the override, never takes it.
**Anchored-bet:** [BET]
**Revisit-when:** Either judge CLI ships a documented, stable machine-readable outage taxonomy (exit codes or a typed error payload) — at which point the text matchers should be replaced by it rather than extended; or codex app-server leaves [experimental] and gains a stability guarantee, at which point the preflight could be trusted enough to reconsider blocking.
