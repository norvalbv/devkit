# ship-merge-verdict-deterministic

## Target · 2026-10-10 — A merge verdict is a deterministic function of paths, line counts, bypasses and captured evidence

**Context:** devkit merges about 19 PRs a day by hand (150 between 2026-09-30 and 2026-10-08), and human review left one written comment across all 150, so the merge click costs time while its benefit is unmeasured. Nothing machine-checkable said which PRs were safe to merge without a person: PR proof is agent-written prose (78 of 150 bodies), and agent PR descriptions are known to claim changes that were never made (arXiv 2601.04886). bun's robobun labels PRs [auto-merge], [human-review] or [policy-decision:dep] from path and size rules, but prints no reason, and both robobun PRs reverted since August had no test proof. The local-regression-evidence-captures-runs-not-causality Target already rules that captured red/green is not causal proof and that ticket relationship and whole-suite sufficiency stay human claims, so a verdict built on that evidence has to say exactly what it asserts.
**Ruling:** devkit's merge verdict is a pure, model-free function of the shipped paths, their numstat line counts, the ship's GUARD_* bypass and waived-finding record, and the red/green evidence outcome. It yields auto-merge-eligible, human-review or policy with reason codes from a closed exported set, listing every reason that fired in precedence order; the first decides. Gate and CI configuration (the gate-input registry's committed paths at any depth, .devkit/config.json, .husky, .github) and the manifests and lockfiles of any ecosystem GitHub's dependency graph reads are always policy. Decision records, the configured consumer-surface globs, any bypass or waived finding, a source diff over maxSourceLines changed lines or maxSourceFiles files (inclusive limits, defaults 50 and 4, from guard.config.json mergeVerdict), and a source change without evidence CAPTURED at the same full head SHA are human-review. Test-only changes are eligible at any size. An input that cannot be read (bypass record, line count, policy, SHA) fails closed to human-review. auto-merge-eligible asserts only that machine evidence was captured at that head, never causality or sufficiency. The verdict is advisory: whatever later lets it merge a PR must record its own Target that explicitly re-targets the human-sufficiency clause of local-regression-evidence-captures-runs-not-causality, with CI green at the same SHA and a shadow readout of verdicts against outcomes as the substitute evidence.
**Consequences:**
- Positive: A PR's merge class is reproducible from facts devkit holds at ship time, and the printed reason tells a reviewer which rule decided it. Because every fired reason is kept, a shadow comparison of verdicts with reverts and follow-up fixes can re-score any single rule without re-running ships. A PR cannot loosen its own verdict by editing gate configuration, CI or the thresholds, and dark telemetry can never read as no bypass.
- Negative: Strict by default. Replayed over the 169 PRs merged to devkit's main from 2026-09-30 00:00 UTC to bf50ee27, with devkit's own globs, no evidence and no bypasses, 9 are eligible as test-only and 19 more would be eligible only with captured proof (28 at most, 17%); 90 touch a decision record and stay human-review. Path rules are blunt: a template's guard.config.json reads as merge-governance rather than consumer surface, a package.json version bump reads as a dependency change, manifests outside GitHub's list count as source, and a test-only change that deletes or skips tests is still eligible. devkit's own consumer-surface list is hand-curated (bin entry points and config-schema owners, not the package's library exports) and goes stale unless someone updates it with each new bin entry or config-schema owner.
**Vision-fit:** n/a — internal ship tooling.
**Researched:** robobun verdict blocks on oven-sh/bun PRs (#44423 [auto-merge], #44846 [policy-decision:dep]; robobun's code is private); pingdotgg/t3code merge model (no required approvals, one aggregate Check job); Mergify conditions (files, #files, modified-lines); GitHub ruleset required_reviewers file_patterns (Team-only beta); GitHub's dependency-graph supported-ecosystems table; arXiv 2601.04886 (agent PR descriptions); arXiv 2209.13978 (change size is a defect-risk feature with no safe threshold); devkit's merge history replayed through the module.
**Rejected:** (a) Mergify or GitHub ruleset file_patterns: loses on inputs. Both run hosted, so neither sees local red/green evidence or ship-time bypasses, and ruleset file_patterns is a Team-only beta enforced only at merge. (b) A model-judged verdict: loses on reproducibility. The same diff could get different classes, and a shadow comparison needs a stable label. (c) t3code's CI-only model with no class: loses on measurement. There is no per-PR class to compare with outcomes, and a dependency bump looks the same as a test fix. (d) robobun's reasonless labels: loses on auditability. A reviewer cannot see why a PR was eligible, and one label hides which rule to tune.
**Anchored-bet:** [BET]
**Revisit-when:** A shadow comparison over at least 100 verdicts shows the eligible class reverted or follow-up-fixed at a higher rate than human-review, which voids the thresholds; or decision-record-only PRs show no reverts over 100 PRs, which makes appended notes a candidate for eligibility.
