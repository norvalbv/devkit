# base-drift-surfaced-at-read-time

## Target · 2026-08-30 — base drift is surfaced when a conclusion is FORMED, advisory and never blocking

**Context:** An autonomous report (bb334bbb -> sc-2297, severity medium) recorded a worktree whose base moved twice underneath it over one long run — 88 files — with nothing anywhere surfacing it. The session header, devkit ship's preflight, the test runner and the gates all kept presenting a consistent picture computed against the base captured at cut time. The concrete near-miss: the agent ran 'git show HEAD:drizzle/meta/_journal.json', saw the chain end at 0090 and concluded migration 0091 did not exist. It already existed on origin. A completeness judge flagged it; the agent re-checked against the same stale HEAD, found nothing, and told the user the finding was a hallucination. Two other files were in the same position. The ticket asked for a base-status command, a ship-time BLOCK, a hardcoded list of generated files, and a worktree flow that re-checks freshness and offers to rebase.
**Ruling:** Base drift is surfaced at READ time, advisory, and never blocks. One shared core (cli/lib/ship/base-drift/) answers 'has origin/<base> moved, and does what moved overlap these paths'; four surfaces consume it — devkit base-status (exit 0/3/4), a SessionStart brief, a PreToolUse advisory, and a print inside devkit ship's --base arm. The trigger is PATH OVERLAP with a caller-supplied set, never a commit count. Freshness is three-valued and a failed fetch degrades to a LOUD 'unknown', never silence. The dedup token folds in the base SHA so a second move re-arms every path. The synced hooks shell out to 'devkit base-status --json' rather than importing the package, and no-op when it is absent.
**Consequences:**
- Positive: Positive: the loss this prevents is booked at read time — the false '0091 does not exist' was asserted hours before any gate ran — so the two hook surfaces fire while the conclusion can still be corrected. base-status gives the feature the one thing nothing else in the ticket had: an exit code CI or a human can assert outside a live agent session. One core means the four surfaces cannot disagree about whether the base moved. Negative: this is the FIRST devkit pre-edit surface that performs network I/O, and it mutates refs/remotes/origin/<base> in the shared clone under sibling worktrees. Bounded to remote-tracking refs (no local branch, index, HEAD or checkout), TTL-cached at 120s keyed on --git-common-dir so N siblings share one fetch, hard-capped at 2.5s, and opt-in as its own component precisely so nobody acquires that obligation without ticking a box. The per-edit half also cannot fire on NEWLY CREATED files — a common shape of work built on a stale read — which is why the SessionStart surface is primary rather than optional.
- Negative: Three costs are paid knowingly. (1) devkit acquires a network dependency on the pre-edit path for the first time, in a repo it does not own — mitigated by the shared 120s window, a 2.5s hard cap, marker-before-fetch so a hung remote costs one window rather than one stall per edit, and opt-in selection, but not eliminated. (2) The per-edit advisory rides PreToolUse additionalContext, which this repo's own decision-log-informs-before-work record calls inconsistently documented upstream; if it is inert the hook is a silent no-op that still costs a node spawn, which is why the verified SessionStart channel carries the primary signal. (3) Scoping the ship print to the --base arm leaves the ship-from-a-checkout-on-main flow uncovered in v1.
**Vision-fit:** n/a — internal devkit tooling (cross-repo guardrail distribution), not a product surface. It stays inside devkit-gates-repo-not-harness: the hooks key on tool_input.file_path, so their SUBJECT is the consumer repository, the same shape as the already-shipped decisions:scope-brief. No carve-out is consumed or widened.
**Researched:** Verified against real git in this repo. 'git merge-base --is-ancestor origin/<base> HEAD' is the only asymmetric probe — origin/<base> != HEAD and the three-dot rev-list --left-right --count are both equally true when HEAD merely carries an unpushed commit, which would make every such checkout a false alarm. FETCH_HEAD is per-worktree, but a hook fetch in the SAME worktree as a running ship would still clobber the value ship-branch.sh:298-303 reads to pin its ephemeral worktree, so --no-write-fetch-head is mandatory rather than hygiene. Default rename detection reports only a rename's DESTINATION, so --no-renames is load-bearing: the agent who read the old name and got nothing is exactly who must be reached. --name-status C-quotes paths containing a tab, newline or quote, and those names are fed straight back into 'git log -- <path>' where a mangled name silently matches nothing, so the diff is parsed with -z. A feature-critique panel returned PROCEED_WITH_CHANGES and overturned two of the original plan's choices: the (session, file) dedup key copied from decision-scope-brief.mjs would have silenced the SECOND move — the one that produced the 88-file divergence — and a per-edit-only design would have missed the read-time class entirely.
**Rejected:** (a) The ticket's ship-time BLOCK — REJECTED: git merges these three-way, so a same-region overwrite already surfaces as a conflict at merge; a block would instead fire on every legitimate concurrent edit of a shared file in a parallel-agent repo, which is the ignorable-signal failure this ticket is about. It prints instead. (b) A signal keyed on commit count or sha inequality — REJECTED: in a shared checkout HEAD never advances as PRs merge, so a count-based indicator is permanently red and gets tuned out; behind is kept as a report field and is never a trigger. (c) The ticket's hardcoded list of generated files (drizzle/meta/_journal.json, .co-occurrence-allowlist.json) — REJECTED: those are frink's layout, and synced-assets-layout-agnostic plus the W-3 invariant forbid baking a consumer's tree into devkit. The AC's real content is a REARM policy, which the base-SHA-keyed token provides for every path without naming any. (d) The offer to rebase — REJECTED: devkit does not mutate a consumer's HEAD. Its non-mutating half, re-checking at task start, ships as the SessionStart hook. (e) Persisting the cut-time SHA at provisioning — REJECTED: devkit does not own the provisioner, and the value goes stale in the WRONG direction — after a rebase every path reads as moved, which is this incident with the sign flipped. merge-base is derived from the two commits that exist now and needs no writer. (f) Duplicating the git logic into the two synced .mjs hooks so they need no binary — REJECTED: ~150 lines twice, outside the typed test surface, tripping the clone gate, and free to disagree with the CLI about whether the base moved; gate-engine/decisions/git-io.mts records the house resolution for exactly this (extract to one home, do not allowlist). (g) The ship print on the DEFAULT arm — DEFERRED: ship-branch.sh:272-284 already refuses any branch that is not on origin, which every provisioned worktree scratch branch is, so it would buy only the ship-from-main flow.
**Revisit-when:** The pre-edit advisory is measured as noise (briefed on paths whose drift never mattered), OR a consumer reports the 120s window costing real network in practice, OR PreToolUse additionalContext is confirmed inert on a supported harness — in which case the SessionStart surface becomes the sole surface and the pre-edit half should be retired rather than kept as dead weight.

- 2026-09-01 — Rejected(a)'s premise — 'git merges these three-way, so a same-region overwrite already surfaces as a conflict at merge' — did not hold for devkit ship itself: ship re-cuts caller content ONTO the refreshed base, so the merge git would have three-way-merged never happens and the revert lands as an ordinary descendant commit (sc-2451). ship-patch-anchored-at-fork-point restores that premise at APPLY time. The rejection of a PATH-OVERLAP block stands unchanged: the new abort is hunk-level, and a base edit and a caller edit in different regions of one file still merge cleanly and never block.
