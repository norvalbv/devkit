# overlay-hook-command-anchor

## Target · 2026-11-19 — Overlay agent-hook commands carry the overlay home's absolute path

**Context:** An overlay install writes devkit's hook scripts only into the overlay home's git-excluded .claude/hooks (and .codex/hooks) and registers them in that clone's .claude/settings.local.json (and .codex/hooks.json). The registered commands found their scripts through $CLAUDE_PROJECT_DIR (Codex: $(git rev-parse --show-toplevel)), which names the session's start directory. A Claude session started inside a linked worktree without --project-config-root (plain claude, claude --worktree, swarm worktrees) loads the home's settings.local.json while $CLAUDE_PROJECT_DIR names the worktree, so every devkit hook - prior-art, the decisions pre-edit guard, the edit-time advisories - exited 127 and failed open with no report. Every Codex session in a linked worktree failed the same way. agent-assets-in-linked-worktrees forbids putting the scripts into worktrees and leaves how a command anchors its script path open.
**Ruling:** In overlay scope, devkit renders each Claude and Codex hook command with the realpath of the overlay home in place of $CLAUDE_PROJECT_DIR, escaped for the double quotes every source command already uses. The registry keeps its single source form; the anchor is a projection parameter resolved once per install, check or remove run from the root that run writes. Shared and package scope keep $CLAUDE_PROJECT_DIR, because their scripts are tracked and present in every worktree, and Cursor stays unanchored. A changed anchor - an upgrade from the unanchored spelling, a moved clone, a Codex scope switch in its one hooks.json - is carried forward as a prior spelling of the same registration, recovered from the ledger row and re-verified by exact re-render, never parsed as shell.
**Consequences:**
- Positive: An overlay hook fires from every linked worktree in every Claude or Codex session, flagged or not, so a gate the consumer selected is never silently absent where agents do most of their work. No file or setting is written into a worktree, and a projectConfigRoot session still loads one registration, so nothing fires twice.
- Negative: The overlay's ledger rows and settings now hold a machine path, so a moved or renamed clone runs no devkit hook until doctor --fix or an upgrade re-anchors it; doctor reports it as a superseded registration. Codex re-asks for hook trust after each re-anchor. Package installs that gitignore /.claude/ stay uncovered, since their settings.json is not read from the main checkout.
**Vision-fit:** n/a — internal tooling
**Researched:** Live probe on Claude Code 2.1.325: in a git worktree add worktree an unflagged claude -p ran an absolute-path PreToolUse hook from the main checkout's settings.local.json while the $CLAUDE_PROJECT_DIR spelling failed. code.claude.com/docs/en/hooks (CLAUDE_PROJECT_DIR is the session's start directory; no placeholder names the main checkout). anthropics/claude-code#83953 and openai/codex#27133, both open. Peer distributors graphify and agentmemory resolve at run time from git rev-parse --git-common-dir. The overlay's core.hooksPath already carries the home's absolute path for the same reason (overlay-self-heal).
**Rejected:** (a) A runtime resolver in every command (dirname of git-common-dir, or git worktree list): it names the git dir for --separate-git-dir and submodule worktrees and fails for bare layouts, applied to shared scope it would run main's copy of a branch-edited tracked hook, cursorCommand would mangle the $(...) form, and it spawns git on every tool call. (b) Copying or linking scripts and registrations into each worktree: ruled out by agent-assets-in-linked-worktrees. (c) Storing the anchor in devkit config: it separates the anchor from the root the run writes, so a moved clone would still write a stale path.

A home whose path holds a control character cannot be written into a command, so its overlay commands keep the unanchored spelling rather than aborting install. devkit's shared spelling found unledgered in an overlay repo's .claude/settings.json is reported as unanchored-duplicate, because the harness no longer deduplicates it against the anchored command.
