# prior-art-before-plan

## Target · 2026-08-06 — Step-0 prior-art validation before any plan exists

**Context:** The Frink wake-hold saga (autonomous report dece9694, sc-1512): five patch Targets in six days on one axis while the dissolving answer sat in a locally cloned reference checkout — mid-saga research surveyed the right projects with the wrong question ('how do others BOUND a background task?', presupposing the wait). Every existing devkit agent is diff- or plan-scoped and asks 'is this change/plan correct?', never 'should this work exist?'. A 2026-08-06 survey found no maintained third-party agent covering web + GitHub code/issue/PR search + a structured cited verdict; every path needed the same wiring, so a thin devkit-owned agent won.
**Ruling:** Problem-shaped work passes through the step-0 prior-art agent AFTER the guard-decisions query — consumer-declared local reference checkouts first, then gh/web — which must challenge the problem's frame and return a cited SOLVED_ELSEWHERE / DISSOLVE_FRAME / GENUINE_NEW_WORK / INSUFFICIENT_EVIDENCE verdict with per-leg availability attestation that planning explicitly acknowledges; advisory-only until paired benchmarks justify any gate; plan-stage reviewer input receives at most a bounded 3-line prior-art summary — full-JSON injection into feature-critique stays rejected until a paired K=3 critique run justifies it, and the 3-line bound is accepted explicitly unmeasured (the 33-row critique baseline does not cover step-0 input); local-kind quotes are read only from consumer-declared research.referenceCheckouts paths and persisted only with explicit opt-in; contract coupling is enforced in the benchmark and, from Phase 4, at capture — the production step-0 path is prompt-level, with one consumer-side check: a GENUINE_NEW_WORK verdict whose own legs show a dark external leg or zero resolved checkouts is recorded as INSUFFICIENT_EVIDENCE in the acknowledgment.
**Consequences:**
- Positive: agents/prior-art.md + skills/prior-art/SKILL.md ship unconditionally via the ordinary sync; skills/brainstorming/SKILL.md carries the step-0 block after the decisions query with a written trigger predicate (new machinery/boundary/dependency; unconditional when guard-decisions show reveals 2+ Target headings on the governing axis) and a spend pre-flight that skips with a note when no external leg is reachable; gate-engine/prior-art/ carries the response contract (verdict-evidence-legs coupling incl. zero-resolved-checkouts attests unavailable, never reached) and the intrinsic bench scored by the parsePriorArt adapter; PriorArtRecordV1 capture is deferred behind the in-flight critique-capture branch and lands as an agent-type registry.
- Negative: The seed corpus is hand-authored — the recorded bootstrap tension against benchmarks-grow-from-telemetry; Phase 5 mines real step-0 outcomes into rows. The genuine-control clean rate (n=5) and decoy ceiling (12 case-clustered slots) are underpowered and carry no hard floors yet. Production coupling enforcement is prompt-level until capture lands.
**Vision-fit:** Completes step 0 of the validate-before-build pipeline: devkit already critiques plans (feature-critique), verifies implementations, and reviews diffs — this adds the only stage that can dissolve the problem itself before any of those run.
**Researched:** t3code/orca verified in Frink's cloned-projects (session-lifetime consumer / pty-driven CLI); third-party survey 2026-08-06: gpt-researcher, langchain open_deep_research, dzhng/deep-research, STORM, smolagents, exa/perplexity MCPs, DeepGit, Cody/Greptile — none fit whole (all web-only or retrieval-only); github-mcp-server is the best GitHub building block but the gh CLI via Bash suffices for a thin agent. Two feature-critique rounds: PROCEED_WITH_CHANGES x2, final CONFIRMED_FEASIBLE / frame SOUND / no blockers.
**Rejected:** Expanding feature-critique instead of a separate agent (phase separation is mechanical: problem vs plan, mutual wrong-phase routing). Adopting a Python research framework (web-only, same GitHub bolt-on needed, alien runtime in a TS toolkit). Full-JSON injection into feature-critique (unmeasured reviewer-input change inside plan-critique-evidence-loop's own scope). Auto-scanning undeclared sibling checkouts (W-3: devkit executes in repos it does not own; suggest, never scan). Hoisting matcher prompt builders into matcher-core (flips the scorer hash of three shipped suites).
**Revisit-when:** The acknowledgment-line count shows DISSOLVE_FRAME verdicts routinely unfollowed; the critique-capture branch merges (unblocks Phase-4 capture); the Phase-3 workflow tier lands (retrieval measured); or the corpus reaches ~30 mined rows, at which point floors and any gating question reopen.

- 2026-08-06 — declaredCheckouts counts glob PATTERNS; resolvedCheckouts counts the DIRECTORIES they expand to (agents/prior-art.md Phase 0). resolved > declared is therefore NORMAL — one cloned-projects/* resolving to five checkouts is the motivating Frink shape. A PR #357 review comment read the pair as a subset relation and asked for a resolved <= declared rule; that was implemented, and the commit-time reviewer gate caught it before it landed: the rule rejected exactly the shape the local-first design exists to serve, and the two corpus rows it would have 'fixed' were correct as written. Only the reverse is impossible (no pattern can expand into a directory), so the parser and corpus lint enforce declared == 0 && resolved > 0 only, with a positive test pinning the one-pattern-many-checkouts case so the tidier-looking rule is not re-derived. The lesson: a plausible-sounding invariant over two counters needs its counters' UNITS checked, not just their arithmetic. What DOES land: the agent md's github leg (an absent gh executable is unavailable, not failed — it contradicted the md's own leg rule two paragraphs above). That file is inside the response fingerprint, so the 15-response K=1 bank goes inert on this commit (backed up at ~/.claude/bench-banks/, keyed to the old fingerprint) and the committed K=1 baseline renders as STALE until an approved run regenerates it; that is honest labelling, not a regression, and nothing gates on it (the hash-drift throw in gate-engine/eval/cli.mts fires only on publish with a predecessor event, and this suite has none). Sequencing chosen so the eventual K=3 pays 45 calls once rather than 30 now plus 45 later. The invariant is now enforced at three layers: parser (resolved <= declared, generalising the earlier declared-0 rule), corpus lint (before any paid call), and the fixture.
