# plan-critique-evidence-loop

## Target · 2026-07-19 — Plan-stage critique evidence compounds without repository artifacts

**Context:** Feature critiques currently overwrite provider-specific runtime files, cannot be safely linked to later outcomes, and prior recovery attempts rewrote measured guidance without valid benchmark evidence or changed commit behavior.
**Ruling:** Keep feature-critique plan-only and preserve its substantive reasoning guidance. Return one strict normalized JSON response; allow one fresh recheck only after a blocking result. Treat Claude, Codex, and Cursor as fresh-install agent targets by default, while activating fail-open private evidence capture only where the audited provider contract exposes the exact completed critique and trustworthy parent-plan correlation. The current capability registry therefore enables capture for Claude and records explicit capability skips for Codex and Cursor; default installation does not imply capture availability. Repo-graph imports sanitized projections through its existing memory layer. Commit gates observe a deterministic would-inject projection only and never change reviewer inputs or outcomes until paired benchmarks justify injection.
**Consequences:**
- Positive: Critiques and atomic edge cases become durable, attributable learning evidence that can improve benchmarks and later reviews without polluting consumer repositories, deleting user provider data, or silently changing commit decisions.
- Negative: The first release deliberately skips ambiguous work bindings and providers without a sufficient callback contract, stores sensitive evidence only with explicit hook opt-in, keeps optional opaque transcripts off by default and bounded when enabled, pays for one treatment K=3 run after the prompt transport changes, and defers implementation review, hard plan-exit enforcement, and commit-prompt injection.
**Vision-fit:** n/a - internal developer tooling that compounds review learning while preserving consumer control
**Researched:** Self-Refine arXiv:2303.17651; CRITIC arXiv:2305.11738; Huang et al. arXiv:2310.01798; CriticBench arXiv:2402.14809; official Claude, Codex, and Cursor hook contracts; existing benchmark-evidence-append-only and bench-gates-on-flips-not-deltas Targets.
**Rejected:** Runtime .cursor or .codex evidence files; flowId or EDGE_CASES_ID; periodic critique of unstable drafts; repeated self-review loops; a fourth repo-graph layer; raw transcripts in SQLite; last-writer-wins evidence selection; default-on broad agent hooks; commit reviewer injection without paired controls.
**Revisit-when:** A preregistered plan-uplift study supports a different retry policy, provider APIs expose stronger stable work identity, or paired commit-reviewer experiments show context injection improves quality without harmful flips.

## Implementation note · 2026-07-22 — Provider defaults are capability-gated

Claude, Codex, and Cursor remain equal fresh-install agent targets. Evidence hooks are a separate capability: they are installed only when a versioned provider contract supplies the completed subagent response and enough stable identity to bind it to the parent plan without transcript inference. The audited first-release matrix is Claude `available`, Codex `parent_plan_correlation_unavailable`, and Cursor `verbatim_response_and_completion_identity_unavailable`. Package-less overlay or standalone installations must likewise report capture unavailable instead of copying runtime machinery into provider directories or installing a command that cannot resolve the shipped runtime. Capability skips are expected, fail-open observations—not provider opt-outs—and must be reassessed against later provider contracts before activation changes.

## Evidence boundary

[Self-Refine](https://arxiv.org/abs/2303.17651) and [CRITIC](https://arxiv.org/abs/2305.11738) show that feedback can improve generation, especially when critique is grounded. [Huang et al.](https://arxiv.org/abs/2310.01798) show that unsupported intrinsic self-correction can instead degrade answers, while [CriticBench](https://arxiv.org/abs/2402.14809) treats critique quality as a capability to measure. Together they justify a bounded, benchmarked policy; they do not establish that one retry is universally optimal.
- 2026-07-27 — The critique benchmark now reports exact response-contract validity separately from semantic observability. For measurement only, exactly one object may be scored when its verdict, frame metadata, and findings pass the bounded semantic projection; unrelated schema failures remain exact-contract failures, and the original provider response remains invalid and production-ineligible. Exact validity remains a shadow metric rather than changing semantic row pass/fail, matching the prior benchmark and the deferred-enforcement rollout. The projection requires the finding text and severity consumed by the matcher but permits a non-empty non-enum lens label; the strict parser still records that label as a contract failure. Intrinsic and workflow rows now exercise the same normalized response contract, Claude benchmark transport unwraps the CLI's single final result, and salvage binds agent/model, corpus, and runner. Fresh probes justified only two narrow critic clarifications: configuration `correct` is a JSON boolean, and the final message has no lead-in or Markdown fence. The audited symlink row uses its fixture-proven Cursor format mismatch as the blocker while unverified traversal remains warning-tier. The pinned Opus K=3 run recorded 23/25 recall, 5/5 clean rows, 2/20 decoy flags, 32/33 verdict accuracy, 33/99 exact-contract responses, and 97/99 semantically usable trials with zero row-level outages; exact reliability therefore remains far below any enforcement threshold, and the semantic comparison is mixed rather than an automatic-merge result.
