# qavis-advisory-gate

## Target · 2026-07-07 — the "deserves QA?" classifier + pass-receipt live in qavis; devkit is a thin fail-open gate that maps its verdict to an exit code

**Context:** qavis (a computer-vision PR QA agent) only ran on an explicit request, so UI-affecting PRs shipped un-QA'd. We wanted `devkit ship` / pre-commit to proactively nudge "run qavis QA" when a change warrants it and stay silent when it doesn't — agent-visibly (a stderr nudge is invisible to a headless shipping agent under output filtering; only an exit code survives). The naive placement — a qavis-specific classifier + a copy of qavis's UI path/ext regex inside devkit — is dead weight for every non-qavis consumer and duplicates logic qavis already owns (`src/route.ts`), and a bench showed that regex (recall 0.45, false-advise 0.39 over a 95-row hard corpus) cannot see semantic UI impact (an API/schema/token/i18n change the UI renders) nor exclude non-UI files under UI paths (tests/stories/types). A first exit-3 design was also unsatisfiable-by-compliance: at commit time no PR exists, so an "already-QA'd" marker always missed and every UI ship blocked with only an override to clear it.

**Ruling:** Split by ownership. (1) qavis owns the classifier (`route --staged|--diff --gate`, a haiku judge that reads the diff — bench-picked at recall 0.96 / false-advise 0.00, clearing the floors regex can't) and a content-addressed pass-receipt (`.qavis/receipt.json`, sha256 over each changed file's blob sha, so a staged index and an identical committed tree match). (2) devkit is a THIN CHANNEL: `gate-engine/qavis-advisory` shells `qavis route --staged --gate`, and fail-OPENS (exit 0) when qavis or a `.qavis/recipe.json` is absent — the fallow precedent, zero weight for non-qavis consumers. (3) The exit contract is advisory: 0 = continue (SILENT / advisory-only on a normal commit / receipt-cleared / qavis absent), 3 = ADVISE under a strict ship (`GUARD_AI_STRICT`) — the ship blocks until qavis runs (writing a receipt that clears it) or an override is set. There is NO exit 1 and NO fail-closed on outage (unlike completeness): an advisor's own failure must never block a ship. Overrides: `GUARD_QAVIS_OK=1` ships without QA, `GUARD_NO_QAVIS_ADVISORY=1` disables. Wired as its own husky fragment (bunx/standalone/overlay) with its own remedy line, NOT an AI_GUARD (different exit contract).

**Consequences:**
- Positive: the block is satisfiable-by-compliance — running qavis clears it and editing after QA re-arms it (proven end-to-end); the classifier isn't duplicated; non-qavis consumers carry zero cost; the model call is spent only on launchable, non-empty diffs (the launchability/empty gate stays deterministic in qavis's `needsVisualJudge`), and a receipt short-circuits a re-ship to zero tokens.
- Negative: the advisory reaches a headless agent only via the exit-3 ship block, not the normal pre-commit path (stderr there is advisory-only); a UI commit in a qavis-recipe repo spends one ~seconds haiku call unless a receipt already covers it; and cross-tool the receipt SHA formula must stay byte-identical between qavis and devkit (documented in both).

**Vision-fit:** n/a — internal dev/CI tooling.

**Researched:** gate-engine/qavis-advisory/{check,cli}.mts; qavis src/{route,route-judge,receipt}.ts + eval/ (95-row bench, results.baseline.json); the completeness gate exit contract (gate-engine/review/completeness.mts); the fallow chain-fail-open precedent (cli/lib/husky/husky-block.mts). A feature-critique pass (RETHINK → resolved) drove the ownership split, the satisfiable-receipt fix, and the flip-table `--fail` for the bench.

**Rejected:** (a) classifier + regex copy inside devkit — REJECTED: dead weight for non-qavis consumers, duplicates qavis's router, and the regex misses the hard cases (bench-proven). (b) a warn-only exit-0 advisory everywhere — REJECTED: invisible to a headless shipping agent (the whole exit-code point). (c) exit-3 with the pass-receipt deferred — REJECTED: unsatisfiable-by-compliance (only a bypass could clear it), the dead-gate anti-pattern.

## Target · 2026-10-11 — A UI change gets a ship-time screenshot instruction from two deterministic rules; devkit no longer calls Qavis

**Context:** The 2026-07-07 Target made devkit a thin channel to Qavis: `qavis route` classified a diff as UI, a receipt cleared it, and a strict ship blocked with exit 3 until a Qavis QA run passed. The QA run could not be relied on. In frink, the only UI consumer, 237 of 238 gate events between 2026-09-01 and 2026-10-10 were could_not_run (bypassed with GUARD_QAVIS_OK or GUARD_NO_QAVIS_ADVISORY). 41 of 64 Qavis runs ended uncertain, mostly because booting the app twice from a clean checkout failed on secrets, seed data, locks or build time, and a median run took about 10.5 minutes. frink removed its Qavis integration on 2026-10-03. What worked was the root agent capturing its own before/after screenshots and adding them to the PR. Long-running agents still forget to do that, so the reminder has to be automated.
**Ruling:** devkit no longer calls Qavis: route, qa, waive, publish, the receipt and its cache shadowing, DEVKIT_SHIP_QA, DEVKIT_SHIP_ROOT/DEVKIT_SHIP_PATHS and the doctor's qavis health line are removed. The `ui-evidence` guard (bin guard-ui-evidence) speaks only at `devkit ship`, keyed on DEVKIT_COMMIT_MSG_FILE, and stays silent on plain `git commit`, `devkit review` and dry-gates. Its hook fragment is `guard-ui-evidence || true`, so it never blocks. It fires on either of two deterministic rules: (1) a staged path matches UI extension globs (tsx, jsx, vue, svelte, astro, html, css, scss, sass, less, minus tests, stories, snapshots, mocks, fixtures and .d.ts), plus globs that guard.config.json `uiEvidence.paths` ADDS; (2) the commit subject, never the body, names a visible symptom as a whole word, which catches a backend bug whose symptom showed in the UI. On fire it emits one advisory row that the ship terminus renders as "advisory, did NOT block this run", leading with the action: add before (base branch) and after (this branch) screenshots to the PR description, or say there that nothing visible changed. The published id `qavis-advisory` maps to `ui-evidence` on read and `devkit upgrade` rewrites config and hook; `--no-qavis-publish` stays an accepted no-op for one release.

The reminder lands in the ship terminus a headless agent reads. On frink's last 200 merged PRs, 20 of 21 PRs that carried screenshots would have been nudged; about 3-4.5% of ships would get a nudge for a change with nothing visible. devkit's own 896 commits since 2026-07-01 trigger rule 1 zero times and rule 2 five times. ## Target · 2026-10-11 — The UI screenshot reminder speaks at every commit, from extension globs or a light model judge over the staged diff; it never blocks

**Context:** The earlier 2026-10-11 Target made the `ui-evidence` reminder speak only under `devkit ship` and replaced Qavis's model router with two deterministic rules. The owner overruled two parts. First, ship is meant to mirror the commit gates, so a reminder that is silent on plain `git commit` gives the two paths different behaviour. Second, the subject-word rule (rule 2) catches a backend change with a visible effect only when the author names the symptom, and it missed frink's one real case (#294). Extension globs alone reach recall 0.41 on Qavis's 95-row trap corpus: every backend-to-UI row and every .ts/.js component is missed.
**Ruling:** `guard-ui-evidence` runs the same path on plain `git commit` and `devkit ship`; it is silent only under `devkit review` and dry-gates. Rule 1 is unchanged and needs no model call: a staged path matches the UI extension globs (minus tests, stories, snapshots, mocks, fixtures, .d.ts) or `uiEvidence.paths`. When rule 1 does not fire, the gate drops staged paths matching those exclusions, markdown and lockfiles. If nothing remains it stays silent. Otherwise the light judge model (`GUARD_REVIEW_MODEL` > `review.model` > the shipped light default, claude or codex) is asked through execJudge whether the change could alter a rendered app screen (web, desktop or mobile), answering VISIBLE or NONE plus one reason. The call has its own 30 s cap, about three times the measured p95 (9.1 s on gpt-5.6-terra@high, 8.3 s on haiku). The prompt is adapted from Qavis's route judge. A backend, API, schema, formatter, i18n or token change whose result a screen renders counts as VISIBLE. Terminal or CLI output and logs count as NONE, because the remedy is a screenshot of a screen. The judge reads the complete list of judged paths plus their staged diff, cut at 6000 characters. Its verdict is cached in `.devkit/ui-evidence-verdict-cache.json` at the main checkout (resolved from git-common-dir), which ship's linked worktrees share.
