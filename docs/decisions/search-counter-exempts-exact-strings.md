# search-counter-exempts-exact-strings

## Target · 2026-09-28 — The search-tool counter counts every in-index grep except exact strings copied from output

**Context:** search-tool-counter (PostToolUse) counted every primary grep toward a 3-call STOP streak, pattern-blind by design: a run of clean-identifier greps is still concept-by-enumeration. That rule lived only in a code comment. Agents diagnosing a gate failure grep for strings copied verbatim from its output ("judge unavailable \(", "NONE are additions"), which the rules route to grep and the semantic index cannot answer better; those greps were flagged conceptual by classify() and then escalated to EXTREME STOP warnings pushing toward a tool that cannot help (sc-3404, a recurrence of sc-1359 / 041e18aa). Low severity, but repeated noise on every diagnosis session.
**Ruling:** Every in-index primary search counts toward the streak EXCEPT a command made only of exact-string content greps, which is a no-op (neither count nor reset, the same transition as an out-of-index target). isExactStringCommand() (search-tool-exemption.mts) decides, conservatively: on the normalize()d command (the same form the counter already classifies: a leading cd prefix dropped and devkit's own rtk token proxy unwrapped, since rtk grep is grep), every command segment starts with a grep-family bin (grep, rg, ripgrep, ack, ag) or a plain output filter (head, tail, wc, sort, uniq, cut) (unquoted redirections such as 2>&1, 2>/dev/null, > out or < in are stripped first: neither separators nor targets) and there is no $(, <(, >( or backtick substitution outside single quotes (an allowlist, because wrappers such as sudo/env and spellings such as f\ind are unbounded; find, fd, echo and everything else count), and every in-scope grep invocation has at least one pattern, only flags the parser fully understands (a per-bin allowlist of short and long flags in search-tool-exemption.mts, the -e forms, and -A/-B/-C/-m context/count flags; anything else such as --files, --exclude, -f, -t or rg -r keeps the command counted), and every pattern (each -e, attached -ePAT, --regexp=PAT, clustered -rne PAT) passes isExactStringSearch(). A pattern passes when it is multi-word, classify() literal, not led by a question word or descriptive phrase once leading punctuation is stripped, contains no word, compared case-insensitively, from the fixed DECLARATION_WORDS list in search-tool-exact.mts (CODE_KEYWORDS plus trait, module, macro, ...), has at least two word-like tokens (lowercase, Capitalized or ALL-CAPS), and carries code punctuation (RE_META_OR_PUNCT minus ?, :, =), a log sentinel word (NONE, TODO, WARN, ...) or underscore constant, or error-message shape. Single tokens and code snippets still count. classify()'s 3-word tier gains the same punctuation / sentinel escapes so the guard stops flagging these strings.
**Consequences:**
- Positive: Agents can grep an exact error or gate string without an escalating STOP message, while identifier enumeration, bare or keyword-wrapped, still escalates toward semantic search.
- Negative: The counter now depends on classify(), so a classifier false-literal can also buy a streak exemption; the exemption is narrowed (no single tokens, no declaration words, no ?/:/= alone, no question leads, two word-like tokens) to limit that. It is a heuristic over a fixed word list: a code search using a declaration word outside DECLARATION_WORDS, or a concept hunt phrased with parentheses or a log-sentinel word, can still slip past. Conservative misses the other way are accepted: any flag off the allowlist (even a harmless --include), any unquoted find word, and log lines containing a declaration word (Cannot find module 'x') keep counting. Any segment outside the grep/filter allowlist (echo, xargs, an env assignment) and any command substitution keep the command counted. Filename-listing modes other than a pattern-less rg --files (ag -g, ack -g) are not recognised.

**Researched:** gate-engine/search-tool/search-tool-counter.mts (pattern-blind rule), search-tool-lib.mts classify() 3-word tier and firstAdvisablePattern; runtime probe showing tokenizeArgv strips the backslash of a double-quoted \( so classify sees a bare (; PRs #345 (sc-1359) and #594 merged without covering this; story sc-3404 triage; prior-art and feature-critique passes; five rounds of ship review findings (snippet bypasses, -e/-f pattern forms, find chaining and wrappers, fd, all-caps log strings, bracketed questions). Round six: find inside command substitution and an out-of-scope fd. Round seven: rg --files and --exclude values misread as patterns, closed by a flag allowlist rather than more parser cases. Round eight: backslash-escaped find, upper-case declarations, and a shared long-flag list; closed by a segment allowlist, case-insensitive matching and per-bin flag sets. Round nine: 2>&1 split as a separator, and an apostrophe inside double quotes hiding a substitution; closed by stripping &-redirections and a quote-state scanner. Round ten: process substitution and redirection tokens read as grep targets.
**Rejected:** Count only flagged calls (the story's ask): reverses the enumeration design — clean-identifier greps would never escalate. Exempt every literal: 'function getUser'/'function getAuth' enumeration would bypass STOP by adding a keyword. Treat any ALL-CAPS token as a literal signal in classify(): acronym-led concept queries (API rate limiting, JWT token refresh, README install steps) would flip to literal and escape both hooks. Detect a backslash escape: the shell tokenizer removes it before classify() runs, so it never fires. Detect find only in command position: wrappers (sudo, env, command, nice, time) are unbounded, so any enumeration misses one. Extend the argv parser flag by flag: grep/rg/ack/ag flag sets are large and bin-specific, so an allowlist that distrusts unknown flags is the only closed form. Detect find/fd by word: shell spellings (f\\ind, $'find', quotes) are unbounded, so only an allowlist of segment heads closes it.

Bypasses closed: punctuated or constant-bearing code snippets, declaration words from other languages (trait, module), only the first -e pattern read, attached/long/clustered -e forms unparsed, a chained or wrapped find (sudo/env/command, /usr/bin/find), fd, -f pattern files, and question words hidden behind a leading bracket. All-caps log strings (ERROR TIMEOUT) were briefly excluded by a lowercase-word rule and now qualify.
