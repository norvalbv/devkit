# cli-cross-process-lock

## Target · 2026-10-18 — One cross-process mutex: a nonce-named holder, reaped only on provable death

**Context:** devkit carried several hand-rolled cross-process locks with different reap rules, and each new feature rediscovered lock fencing one reviewer round at a time (four rejected designs in a row while building the ship queue). The overrides store lock stole any lock older than 30 s and released by unconditional unlink: a paused waive or reconcile lost its lock to a second writer, then deleted that writer's lock on exit, so a third writer entered and a recorded waiver could be silently dropped. Locks that never reap instead wedge until a human deletes a crashed process's lock.
**Ruling:** gate-engine/judge/process/process-lock.mts (withProcessLock, reapIfDead, LockHeldError) is devkit's one cross-process mutex. The lock is a directory renamed into place already holding one file NAMED by the holder's nonce (pid + OS start identity), so it is never ownerless. A holder is reaped only when processOwnerIsProvablyGone proves it dead, by renaming exactly <lock>/<nonce> away then rmdir (atomic compare-and-delete); there is NO age-based reap, and release removes only its own nonce. The critical section is synchronous; a nested acquire of a lock the same process holds fails at once with LockHeldError; a contended acquire waits (5 s default, liveness re-checked every 250 ms) then throws LockHeldError naming the holder pid. Staged and grave siblings end in .lock so a consumer's .devkit/*.lock ignore hides crash leftovers. The ship queue (slot.lock, seq.lock) and the correctness-overrides store lock (<store>.mutex.lock) run on it; a new cross-process lock uses it or records here why it cannot.
**Consequences:**
- Positive: A paused but live holder (SIGSTOP, a slow disk, a laptop sleep) keeps its lock however long it takes, so no read-modify-write is lost; a crashed holder is recovered automatically by the next acquirer with no human step; one vetted shape replaces per-feature lock design.
- Negative: Liveness costs a ps fork per reap check (bounded to one per 250 ms of contention). A holder that is alive but wedged is never reclaimed: the waiter times out with the pid and a human must stop that process. The overrides lock moved from <store>.lock (a file) to <store>.mutex.lock (a directory) so an older devkit's leftover lock file cannot make the rename fail; while an older and a newer devkit both run against one store (e.g. the checkout's guard-review and a ship worktree's gate) they do not exclude each other, accepted as short-lived on a single-consumer toolkit. Sync-only: an awaiting critical section needs a separate async variant.
**Vision-fit:** n/a — internal tooling
**Researched:** Prior-art pass: proper-lockfile and npm lockfile reap by mtime age (proper-lockfile lib/lockfile.js isLockStale); os-lock is async-only; fs-ext ships no prebuilds; Node core declined flock (nodejs/node#49256); fs-native-extensions 1.5.1 offers a prebuilt flock released on holder death (darwin smoke test: SIGSTOPped holder keeps it, SIGKILLed releases it). Peers (t3code, SocratiCode) accept proper-lockfile's 120 s age reap. Revert proof: the old overrides lock ran fn over a live holder whose lock was 60 s old; the new one throws LockHeldError and leaves the holder intact.
**Rejected:** (a) Age-based reap (the old overrides 30 s steal, proper-lockfile's stale window): loses on correctness, it evicts a paused live holder and loses its update. (b) A kernel flock via fs-native-extensions: loses on surface, it adds a native addon to every consumer and a second lock shape beside the bash-held ship-queue slot that a flock cannot cover (ship-machine-wide-queue Rejected (a)); a nested in-process acquire on a second fd self-deadlocks. (c) Keeping per-feature locks: loses on cost, each re-learns fencing through reviewer rounds.
**Anchored-bet:** [BET]
**Revisit-when:** A devkit lock must stay held across an await or a bash span the nonce lock cannot model, or ps-based liveness checks measurably slow a contended gate (more than one fork per 250 ms observed), or a kernel lock becomes available without a native addon (Node core ships flock).
**Scope:** gate-engine/judge/process/process-lock.mts,gate-engine/review/overrides.mts
