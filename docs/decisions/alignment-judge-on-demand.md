# alignment-judge-on-demand

## Target · 2026-10-06 — The alignment judge runs on demand, not in the generated hook

**Context:** AGENTS.md, the decisions skill, the feature-critique agent and the pre-edit brief hook all said guard-decisions check-alignment --gate blocks, at commit, code that contradicts a scoped Target. No devkit-generated hook has ever called it: the decisions fragment emits only detect --gate, and the hook fragment planned alongside the gate was never built. Agents acted on the false claim. One narrowed a new Target's Scope to avoid a per-match judge cost that does not exist, leaving a known gap in that ruling's reach, and wrote the invented cost into the append-only log; a consumer repository copied the blocking claim into its own agent rules. Dozens of Scope notes in this log say a glob arms the alignment gate, so a reader believed a dedicated judge ruled on every scoped Target at commit when none did. The feature-critique agent's own alignment step ran the command with no mode, which prints usage and judges nothing, so that step had never checked anything either.
**Ruling:** No devkit-generated hook runs check-alignment. It stays a shipped, maintained, on-demand command: an agent or human runs it on a staged change, or a consumer hand-wires it outside the managed block, which doctor already leaves alone. A Scope glob decides where a ruling is LOADED; it arms no dedicated gate. At commit the generated hooks load scoped Targets into three judges that each have another primary job: the detect judge (is this an unrecorded decision), the security and performance reviewers' Targets block, and, when the review guard is selected, the commit-msg completeness judge, which loads up to six scope- or semantically-matched Targets and can block a change that contradicts one. None of them is the per-Target alignment judge: no ALIGN / CONTRADICT verdict is produced per scoped Target at commit, and a Target outside the loaded six, or a repo without the review guard, gets no contradiction check there. Before work, the scope brief and feature-critique (reading guard-decisions scoped-targets for the paths a proposal touches) carry the ruling. The warn-only depth pass lives in check-alignment, so it does not run at commit. Docs that name a guard --gate call must be backed by a generated hook block or listed as on-demand, pinned by cli/__tests__/doc-gate-claims.test.mts.
**Consequences:**
- Positive: Docs, agent briefs and the hooks agree, so an agent weighing a Scope glob prices it correctly: widening a Scope adds no dedicated judge run at commit. Consumers get no new latency and no new false blocks. What commit-time coverage exists is named for what it is, so nobody is told a dedicated guard rules on every scoped Target.
- Negative: Contradiction coverage at commit is partial and shared: it depends on the review guard being selected and on the Target being among the six the completeness judge loads, inside a prompt whose main duty is completeness. The dedicated flip-flop guard this log was partly built for is advisory in practice. The maintained strict-ship outage path and ALIGN verdict cache in check-alignment serve only on-demand and hand-wired runs.
**Vision-fit:** n/a — internal tooling. Serves the consumer-seat rule: a gate that false-blocks, or a doc that names enforcement which does not run, costs trust in every repo that installs devkit.
**Researched:** Hook generator history (no call site in any generated hook or ship script, ever). cli/lib/husky/commit-msg-block.mts and gate-engine/review/completeness.mts (the completeness judge loads scopedTargets, top 6, and its brief makes a contradicted Target a finding). docs/benchmarks/decisions-findings.md: alignment CONTRADICT precision 0.80 [0.49, 0.94], macro-F1 0.63, escalation on 58.8% of rows. check-alignment runs one agentic judge per matching Target, serially, 240s cap per pass. Reviewer Targets framing in gate-engine/review/evidence/targets-block.mts. arXiv 2602.07609 (LLM detection of architectural decision violations): model output is best used as guidance or early warning rather than a final decision. Peer practice: deterministic fitness functions (ArchUnit) block in CI; LLM-judged ADR conformance ships as reviewer context.
**Rejected:** (a) Wire check-alignment --gate into the generated hook with detect's exit contract — LOSES: a file central to this repo matches roughly six to nine scoped Targets, each a serial agentic judge with a 240s cap and frequent escalation, so a commit could wait many minutes; at 0.80 block precision about one block in five is false; and every pinned consumer with the decisions guard would gain a new blocking LLM gate on upgrade. (b) Keep the docs and say the other commit-time judges replaced it — LOSES: they read at most a capped subset of Targets inside prompts with other primary duties and give no per-Target verdict, so calling that the alignment gate would overstate it the same way the old docs did. (c) Delete check-alignment — LOSES: it is a published bin subcommand consumers may have hand-wired, and its scope loader and matcher are what drift, the scope brief and the commit-time judges reuse.
**Anchored-bet:** [BET]
**Revisit-when:** The alignment bench's CONTRADICT precision lower bound reaches about 0.9 AND per-commit cost is bounded (parallel or batched judging, or a cap on Targets judged per commit). Then ship it as an opt-in guard component, never a default-on change for pinned consumers.
