# vendored-third-party-agent-assets

## Target · 2026-07-29 — Vendor third-party agent assets, pinned by upstream commit SHA + content hash

**Context:** devkit wants to offer third-party agent assets (skills, and later agents/hooks) that it does not author. The first is i-have-adhd — an MIT-licensed, single-file output-style skill with 13k stars whose upstream publishes NO tags or releases. Two ways to deliver it: shell out to the upstream installer, or vendor the bytes into devkit's own bundle. devkit already syncs three agent surfaces (.claude, .agents for Codex, .cursor), records every synced file's sha256 in a .devkit manifest, and removes assets by deselection — a delivery route outside that model is invisible to doctor and unremovable by clean.
**Ruling:** Vendor third-party agent assets into devkit's own skills/ tree, pinned by FULL upstream commit SHA plus a sha256 of the vendored bytes (cli/lib/install/vendored-skills.mts, asserted by vendored-skills.test.mts). Delegating to the upstream installer ('claude plugin marketplace add' + 'claude plugin install') is REJECTED: Claude-only, writes to the user's GLOBAL config rather than the repo, needs the network at install time, and cannot be drift-checked or deselected. A SHA rather than a version range because these upstreams publish no tags — the SHA is the only stable identifier for the bytes that were reviewed. The upstream LICENSE ships BESIDE the asset rather than being folded into its frontmatter: that satisfies MIT attribution while keeping the asset byte-identical to upstream, so the recorded hash stays an exact upstream comparison. Pin refreshes are a deliberate maintainer act via scripts/sync-vendored-skills.mjs (network; never called by init/upgrade).
**Consequences:**
- Positive: A consumer install performs no network fetch and depends on no external installer, consistent with zero-consumer-tool-deps. Vendored assets ride the existing syncSkills pipeline, so they reach all three surfaces, appear in skills-manifest.json, are drift-checked by doctor, and are reclaimed on deselection with no separate uninstall path. An accidental local edit fails the suite. The cost: devkit carries a copy that does not track upstream automatically — an upstream improvement reaches consumers only when a maintainer bumps the pin and reviews the diff.
- Negative: Deliberately trading automatic upstream freshness for provenance, auditability, and multi-surface reach. Accepted because the reviewed-bytes guarantee matters more for content that shapes agent behaviour in every consumer repo than same-day updates do, and because an unpinnable auto-updating install cannot be reviewed at all.
**Vision-fit:** devkit's contract is that everything it installs is owned, inspectable, and removable. An asset devkit offers but cannot verify or remove would be the first exception.

Ships as the opt-in 'adhd' component — off even under --yes, since it reshapes how the assistant writes. Only SKILL.md + LICENSE are vendored; upstream's skills/i-have-adhd/agents/ (gemini.toml, openai.yaml) is deliberately NOT copied, as it configures harnesses devkit does not target and syncSkills would push it into every consumer's .claude/skills as noise. Upstream's opt-in SessionStart always-on hook is out of scope for this change: it needs a hook script, a HOOK_REGISTRATIONS ledger entry, and a rewrite of its ${CLAUDE_PLUGIN_ROOT} path assumption, and the skill is usable without it via /i-have-adhd.
- 2026-07-30 — i-have-adhd is now ALWAYS-ON by selection, not a second opt-in: adhd:true installs the vendored skill AND a SessionStart hook (agents-hooks/adhd-session-start.mjs) that injects the skill body as additionalContext. Rationale: the skill sets disable-model-invocation, so nothing but a hook can ever start it, and requiring /i-have-adhd every session is the wrong ergonomics for a reading-accessibility preference. Mechanism copied from frink's ponytail-frink plugin (read SKILL.md, strip frontmatter, emit hookSpecificOutput.additionalContext) rather than invented. NOTE this is additionalContext, NOT the system prompt — same privilege as a skill body; the gain is that it is automatic, precedes turn one, and the matcher includes 'compact' so it is re-asserted when a compaction would otherwise let the style decay. Cost measured at ~1.5-1.8k tokens per injection (6393-byte body), ~1.2x devkit's own CLAUDE.md and ~0.7x ponytail-frink's 9069-byte body, re-paid per compaction. Durable off switch is .devkit/adhd-off (gitignored, since committing it would impose one reader's preference on the team); devkit appends that instruction as a footer at inject time so the vendored SKILL.md stays byte-identical to its pin. Upstream ponytail's richer controls (intensity modes, UserPromptSubmit mode tracker, statusline) are deliberately NOT ported — they cost a node spawn per prompt.
- 2026-07-31 — The vendored skill now installs to .devkit/vendored-skills/<name>/, NOT the agent skills dirs. .claude/skills/ (and its Cursor/Codex twins) is where the CONSUMER's hand-authored skills live; a pinned third-party copy devkit owns, drift-checks and reclaims does not belong sitting among them, indistinguishable from the reader's own work. Delivery is now a plain two-file copy (cli/lib/install/adhd-skill.mts) called from init and the overlay, so the component no longer depends on skills being on, and skillNamesForSelection returns a constant false for the name — that exclusion is ALSO the whole migration, since syncSkills' existing manifest reclamation deletes a previously-manifested skill dir the moment it leaves the selected set (verified on both surfaces against both the v2 and legacy manifest schemas). No bespoke upgrade step. .devkit/ was chosen over a new top-level dir because devkit already owns that tree: clean removes it wholesale and the overlay git-exclude already covers it, so the relocation added no removal or ignore machinery — only a doctor presence-check, replacing the drift coverage the skills manifest used to provide indirectly. Cost: /i-have-adhd no longer resolves as a slash command (skill discovery only scans the agent skills dirs), so the SessionStart hook is now the ONLY way it runs — acceptable because the skill sets disable-model-invocation and the 2026-07-30 note already made the hook its only real entry point; the loss is re-invoking it by hand after 'stop adhd mode'. Reclaim here is deliberately NOT pristine-checked, unlike the agent skills dirs: clean already deletes .devkit/ unconditionally, so honouring a local edit in one path but not the other would be the inconsistency rather than the safeguard. REJECTED again, more specifically than on 2026-07-29: shipping it as a real Claude Code plugin (.claude/plugins/<name>/ + enabledPlugins), the shape frink's ponytail-frink uses. Enabling ANY plugin — project-scoped or not — records marketplace and install state in the USER's global ~/.claude/plugins/*.json and loads from a versioned global cache, which is the same global-config objection that killed the upstream installer; activation also needs a committed extraKnownMarketplaces key that would turn a personal reading preference into a team-wide default and write into every teammate's home dir — the exact inversion of gitignoring .devkit/adhd-off.
- 2026-08-01 — i-have-adhd now also registers a UserPromptSubmit anchor (agents-hooks/adhd-prompt-anchor.mjs), not just the SessionStart body. Evidence: the body enters context once and then sits at a fixed early position while the conversation grows — measured on this machine's own transcripts at up to 30 user turns and a peak of 1,002,118 context tokens between re-assertions. Instruction adherence falls over exactly that distance (MMMT-IF, arXiv 2409.18216: code-verified compliance 0.81 at turn 1 to 0.64 at turn 20 across Gemini 1.5 Pro / GPT-4o / Claude 3.5 Sonnet), and the intervention with direct causal evidence is proximity to the point of generation, not a higher-privilege channel: re-stating the constraints at the END of context recovered +22.3 points there, while the instructions had never left their original privileged position. Compaction is NOT the gap — SessionStart re-fires with source=compact and self-heals (verified against a real auto-compaction: preTokens 1002118, postTokens 20195). The gap is the long stretch between compactions. The anchor is deliberately ONE line restating only the rules that decay first, never the ~6.4KB body: redundant reinforcement is not free, and repetition reinforcing one instruction has been measured degrading adherence to others by up to 21.2% (arXiv 2602.04294), alongside the general irrelevant-context distractibility results (2302.00093, 2502.04362). Its closing clause preserves the skill's own explain-fully carve-out, without which a terse anchor pulls explanatory answers short. REJECTED: a fixed periodic cadence (every N turns) — no controlled sweep of reminder intervals exists in the literature, so any specific N would be invented; an output style is the only true system-prompt placement Claude Code offers but costs the single global outputStyle slot, defaults keep-coding-instructions to false (silently REPLACING the built-in coding instructions), is Claude-only, and per the same evidence would not fix drift anyway since it stays pinned at position 0. Note for future readers: hook additionalContext is normally delivered as a user-role system-reminder message, but 2.1.220 gates a genuine mid-conversation role:system path (beta mid-conversation-system-2026-04-07) whose exclusion list stops at claude-opus-4-7 — 4.8 and the 5-series fall through to a remote flag, so on those models this anchor may already arrive with true system authority. Cost is ~48 tokens per turn plus one node spawn; the spawn objection that kept the upstream ponytail tracker out is weaker here because consumer repos already spawn a UserPromptSubmit hook per prompt.
