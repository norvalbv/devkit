# vendored-third-party-agent-assets

## Target · 2026-07-29 — Vendor third-party agent assets, pinned by upstream commit SHA + content hash

**Context:** devkit wants to offer third-party agent assets (skills, and later agents/hooks) that it does not author. The first is i-have-adhd — an MIT-licensed, single-file output-style skill with 13k stars whose upstream publishes NO tags or releases. Two ways to deliver it: shell out to the upstream installer, or vendor the bytes into devkit's own bundle. devkit already syncs three agent surfaces (.claude, .agents for Codex, .cursor), records every synced file's sha256 in a .devkit manifest, and removes assets by deselection — a delivery route outside that model is invisible to doctor and unremovable by clean.
**Ruling:** Vendor third-party agent assets into devkit's own skills/ tree, pinned by FULL upstream commit SHA plus a sha256 of the vendored bytes (cli/lib/install/vendored-skills.mts, asserted by vendored-skills.test.mts). Delegating to the upstream installer ('claude plugin marketplace add' + 'claude plugin install') is REJECTED: Claude-only, writes to the user's GLOBAL config rather than the repo, needs the network at install time, and cannot be drift-checked or deselected. A SHA rather than a version range because these upstreams publish no tags — the SHA is the only stable identifier for the bytes that were reviewed. The upstream LICENSE ships BESIDE the asset rather than being folded into its frontmatter: that satisfies MIT attribution while keeping the asset byte-identical to upstream, so the recorded hash stays an exact upstream comparison. Pin refreshes are a deliberate maintainer act via scripts/sync-vendored-skills.mjs (network; never called by init/upgrade).
**Consequences:**
- Positive: A consumer install performs no network fetch and depends on no external installer, consistent with zero-consumer-tool-deps. Vendored assets ride the existing syncSkills pipeline, so they reach all three surfaces, appear in skills-manifest.json, are drift-checked by doctor, and are reclaimed on deselection with no separate uninstall path. An accidental local edit fails the suite. The cost: devkit carries a copy that does not track upstream automatically — an upstream improvement reaches consumers only when a maintainer bumps the pin and reviews the diff.
- Negative: Deliberately trading automatic upstream freshness for provenance, auditability, and multi-surface reach. Accepted because the reviewed-bytes guarantee matters more for content that shapes agent behaviour in every consumer repo than same-day updates do, and because an unpinnable auto-updating install cannot be reviewed at all.
**Vision-fit:** devkit's contract is that everything it installs is owned, inspectable, and removable. An asset devkit offers but cannot verify or remove would be the first exception.
