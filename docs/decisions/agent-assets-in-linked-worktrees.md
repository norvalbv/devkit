# agent-assets-in-linked-worktrees

## Target · 2026-10-19 — devkit does not project agent-session assets into linked worktrees; the harness delivers them

**Context:** An overlay install, and a package install in a repository that gitignores /.claude/, writes devkit's agent-session assets into the main checkout only, git-excluded: agent briefs under .claude/agents, skills under .claude/skills, hook scripts under .claude/hooks, and hook registrations in .claude/settings.local.json (overlay) or .claude/settings.json (package). A linked worktree, which agent tools create constantly, holds none of them. The one overlay consumer measured had 211 linked worktrees, of which 1 held the hook scripts. The open question was whether devkit should project these assets into each worktree, the way the overlay projector already does for gate inputs. No devkit gate depends on them: reviewer briefs resolve from the package or a consumer override.
**Ruling:** devkit does not copy, link or project agent-session assets (agents, skills, hook scripts, hook registrations) into linked worktrees: not through the gate-input registry, not through the overlay worktree projector, not through doctor --fix, and not through a git hook. Delivering them to a session is the agent harness's job. Claude Code reads the main checkout's .claude/settings.local.json from any worktree, reads untracked .claude/skills, .claude/agents and .claude/commands through from the main checkout when the worktree has no such directory, and with --project-config-root (SDK projectConfigRoot, which Claude Desktop and Frink pass for every worktree session) resolves hooks and $CLAUDE_PROJECT_DIR from the main checkout while devkit's hooks act on the worktree named by the stdin cwd. How a hook command anchors its script path is outside this ruling.
**Consequences:**
- Positive: A session launched in project-config-root mode gets the same devkit agents, skills and hooks in a linked worktree as in the main checkout, with no devkit code. Each worktree carries no second mutable copy of the agent half that would need staleness checks, doctor rows and clean support, and the gate-input registry keeps listing only paths a gate reads, so ship and review never freeze or drift-check agent assets.
- Negative: These configurations stay uncovered. A Claude session started without --project-config-root (plain claude, claude --worktree, swarm worktrees) loads the registrations but its "$CLAUDE_PROJECT_DIR/.claude/hooks/<script>" paths resolve under the worktree, so every devkit hook fails open as a non-blocking error (live probe on Claude Code 2.1.302: rc 127). An overlay consumer that tracks its own .claude/skills or .claude/agents gets no read-through, so devkit's skills and agents are absent in an unflagged worktree session. A package install that gitignores /.claude/ registers hooks in .claude/settings.json, which is not read from the main checkout, so an unflagged worktree session registers no devkit hooks. Codex discovers project hooks from the primary checkout but devkit anchors them at $(git rev-parse --show-toplevel), the worktree, so they fail in every linked worktree, and .agents/skills loads from the worktree only. Cursor is unverified. In all of these the decisions guard's pre-edit deny hook, installed on every selected agent surface, does not run. The read-through needs Claude Code 2.1.211 (settings.local.json) and 2.1.277 (skills, agents, commands), and devkit checks neither.
**Vision-fit:** n/a — internal tooling
**Researched:** Claude Code docs (code.claude.com/docs/en/worktrees, "What worktrees share with the main checkout"; code.claude.com/docs/en/settings, where the local file lives in a git repository). A live probe on Claude Code 2.1.302 in a scratch repository with a gitignored .claude/ and a git worktree add worktree, with and without --project-config-root. anthropics/claude-code#83953 (project-scope hooks do not reach git worktrees, open). openai/codex#27133 (project hooks ignored inside a git worktree, open). Frink's worktree chats passing projectConfigRoot (benord-labs/frink #401) and devkit's hooks taking their workspace from the stdin cwd (#1109). A census of the overlay consumer's 211 linked worktrees.
**Rejected:** (a) Registry entries flagged overlayWrites in gate-engine/deterministic/gate-inputs.mts: the registry lists paths a gate reads, and ship, review, excludes and clean all derive from it, so agent assets would be linked, frozen and drift-checked as gate inputs. (b) A post-checkout hook that projects on git worktree add: skipped for --no-checkout and for worktrees made from an unlinked worktree, the same coverage loss that ruled it out for gate inputs. (c) Per-worktree copies or links of the agent half: a second mutable copy per worktree, and Claude Code itself writes settings.local.json, so a link is replaced by a real file on its next write. (d) Extending the overlay projector or doctor --fix: they run at commit, doctor, ship and review time, after a session has already loaded its configuration. (e) Emitting a .worktreeinclude: it copies, applies only to worktrees Claude Code creates, and a copied .claude/skills directory switches off the read-through and goes stale. (f) A WorktreeCreate hook: it replaces git's worktree creation outright for every worktree the harness makes.
