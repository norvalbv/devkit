# ship-gates-converge-not-restart

## Target · 2026-07-03 — a killed or failed ship RETRIES cheap and monotone: verdicts checkpoint + cache, deterministic failures aggregate, AI outages fail closed (ship-only)

**Context:** A shipping agent in frink looped 5 `devkit ship` attempts (~40 min) and never landed: the gate chain's real worst case (~4 min deterministic prefix + decisions cascade + a 300s+420s reviewer cascade ≈ 1800s) exceeded both the 900s `SHIP_COMMIT_TIMEOUT` and the 10-minute foreground tool cap, guard-review discarded finished PASSes on a kill (batch save after `Promise.all`), every retry re-ran the identical deterministic gates (~4 min each), and the 124 banner blamed "likely a hung gate", sending the agent chasing a phantom hang instead of the budget.
**Ruling:** Ship retries CONVERGE instead of restarting: (1) reviewer PASSes checkpoint per-completion, (2) an all-green deterministic prefix is cached on the staged tree hash (`guard-prefix`, armed only under `DEVKIT_SHIP=1` where worktree ≡ index), (3) decisions ROUTINE/ALIGN/depth-PASS verdicts are cached on their exact evidence bytes, (4) deterministic gate failures AGGREGATE into one report while AI gates stay fail-fast, and (5) under `GUARD_AI_STRICT=1` (exported only by ship) the reviewer gate's sonnet first pass retries once and an inconclusive-after-retry FAILS CLOSED with exit 3 — a code distinct from exit 1 so hooks never render an outage as an opus-confirmed FAIL; the decisions judges fail closed WITHOUT a retry (deliberate: retries there erode the ceiling for little value — alignment outage exits 3 named, detect's outage keeps its regex block standing but labels it UNVERIFIED with a remedy). Default `SHIP_COMMIT_TIMEOUT` rises to 1800s with the honest full-chain equation documented; the timeout banner names the mid-flight stage + unfinished reviewers and says "re-run to converge".
**Consequences:**
- Positive: A killed ship keeps every earned verdict — the frink 5-attempt loop becomes ~2 attempts with the second paying only for unfinished work; agents get one aggregated deterministic report per cycle instead of N fail-fast round trips; a judge outage on a ship blocks loudly with a remedy instead of silently skipping review.
- Negative: Three cache files under `.devkit/` that can go stale against gitignored inputs (the search-code index behind guard-dup) — `guard-prefix clear` / `guard-review clear-cache` are the escape hatches; strict mode makes `claude` availability a hard ship dependency (by design: do it well or don't); exit 3 is new contract surface hand-authored consumer hooks must learn.
**Vision-fit:** n/a — internal tooling (devkit is dev infrastructure).
**Researched:** frink session forensics (5 attempts, exit 143 then 124, gates re-passing identically); guard-review's existing diff-keyed cache (the checkpoint gap was the save timing, not the keying).
**Rejected:** (a) run-all-and-aggregate for AI gates too — LOSES: a wall of AI findings raises agent confusion/hallucination risk (maintainer ruling: incremental fixes for AI verdicts). (b) fail-open on AI-gate timeout — LOSES: a ship silently skipping the reviewer gate defeats its purpose; maintainer ruled "we do it well, or don't do it". (c) keeping 900s and shrinking judge timeouts to fit — LOSES: truncates legitimate checklist-driven investigations to buy a number.
**Anchored-bet:** convergence machinery (checkpoints + caches) is the backstop for any future budget misfit — the ceiling is a hang guard, not a schedule.
**Revisit-when:** ship retries still exceed 2 attempts on unchanged diffs (cache misses in practice), or a deadline-aware judge clamp (`DEVKIT_GATE_DEADLINE`) becomes necessary because single attempts routinely blow the 1800s ceiling.
**Scope:** gate-engine/prefix-cache/**,gate-engine/review/**,gate-engine/decisions/verdict-cache.mjs,gate-engine/judge/verdict-store.mjs,cli/lib/ship/commit-with-gate-capture.sh,cli/lib/husky/husky-block.mjs,.husky/pre-commit

- 2026-07-03 — ship does NOT auto-retry after a 124 — the banner instructs a manual re-run. Auto-retry rejected: on a genuinely broken setup (claude offline / a real hang) it re-bills the full AI cascade every cycle; the harness already re-invokes agents on background completion; and the informative 124 banner (mid-flight stage, unfinished reviewers, how to converge) must not be hidden behind a silent loop. Consistent with the Target's anchored-bet — the ceiling is a hang guard, not a schedule.
- 2026-07-04 — strict reviewer first-pass cap raised 300→420s (= the escalate cap) so a judge merely CONTENDED (parallel-`claude` CPU/subscription pressure), not workload-slow, finishes on its ONE pass instead of being SIGTERM'd into a spurious exit-3 (sc-1048; observed at ~301s on a large frink ship where 3/5 judges had already PASSed and auth was healthy). The "TIMEOUT is not retried" invariant is KEPT — the extra budget is given UP FRONT, not as a re-run. Chosen over an inline backed-off retry (throws away the ~300s the judge already invested; N judges re-correlate their retries under the same contention; raises worst-case) and over the anticipated `DEVKIT_GATE_DEADLINE` clamp (not yet warranted — a single attempt stays ≤420s, under the 600s foreground cap; the 1800s ceiling is unbroken). Complements the concurrency cap (sc-1050) that stops judges self-saturating in the first place. Consistent with the anchored-bet — the cap now reflects real investigation time, still a hang guard, not a schedule.
- 2026-07-07 — deterministic-prefix cache key now folds in a gate-config fingerprint (resolved guard.config.json minus cwd, whole eslint/baselines contents, search-code index size:mtime, jscpd availability+version) — hardening the gates or wiring a gitignored input (indexPath, a baseline, a jscpd install) auto-invalidates a PASS earned under the weaker config. Narrows the Target's accepted 'caches can go stale against gitignored inputs' negative to near-zero for config/baseline/index/jscpd; guard-prefix clear stays the manual hatch. Depends on the ship linker symlinking those inputs into the worktree so the fingerprint reads real state (an unlinked input reads 'absent', still flips the key once linked). Fail-safe: an unreadable config yields a null key so the gates run.
- 2026-07-24 — One supervised gate-capture path for ship/reship/review (sc-1199). Ship/reship previously took a second, weaker path — coreutils `timeout` plus a bare `  tee` — whose process-group kill fired ONLY on expiry. A reviewer that REJECTED exited in seconds, so the ceiling never fired, and any child the gate leaked kept the capture pipe's write-end open: `tee` never saw EOF, the run never returned, its EXIT trap never ran, and the ephemeral worktree stayed checked out, blocking the re-ship of the corrected snapshot. The supervisor now also reaps on this path: once the leader exits with a group still alive, a 5s linger grace precedes the same group-kill escalation, and the leader's status SURVIVES the reap so a rejection is never reported as a timeout (a converge-and-retry hint for a verdict that cannot converge on its own). Chosen over (a) a bounded tee-drain on the weak path — unwedges the shell but leaves the leaked judge tree alive burning subscription quota, and (b) spawning judges detached — puts them in their own group, which is precisely what the supervisor's escape-adoption exists to chase, and fixes only one leak source. Consequences: hang protection no longer depends on coreutils being installed (node + /bin/ps only), which retires that dependency for consumers and un-gates three hung-gate tests that never ran on stock macOS; the telemetry archive is now probed before it reaches tee so an unwritable path still cannot fail a ship; expiry is exactly 124 and 137 now unambiguously means the supervisor itself was SIGKILLed. Cost: one extra node startup (~50-100ms) per ship for the adoption pass, and a rejection now takes ~5-15s to return instead of exiting instantly when the gate leaked.
- 2026-07-24 — Prerequisite uncovered while landing the above: `signalGroup` threw on EPERM from `kill(-pgid, sig)`. macOS returns EPERM — not ESRCH — while it is still reaping a group's members, and the supervisor already documented that window but wired the tolerance for the `signal === 0` liveness probe ONLY. A real SIGTERM landing in the same window threw, became terminalFailure, and settled the supervisor at 1. Measured on macOS under parallel load: 39 of 40 supervised runs took EPERM on the group SIGTERM. It stayed latent while `devkit review` was the only supervised caller (its adoption pass is the sole reader of that status, and review runs rarely and alone); the moment ship joined, the adoption pass began flipping rc to 1 on commits that had ALREADY LANDED with every gate green — 7-12 intermittent failures across a 2000-test run, all passing in isolation. EPERM is now tolerated for any signal, reported as 'group still present' so the existing poll loop settles it on ESRCH — the same conservative reading the probe already took. Rejected: scoping the adoption pass's rc escalation to review only, which would have hidden the defect behind a mode branch, left it live for review, and traded a real reap signal for a policy divergence.

- 2026-08-04 — sc-1420 — ship now VERIFIES the objects its index names, and attributes their loss to the object database rather than to a gate. Two checkpoints (after staging, and at the pre-commit preflight) run ship_assert_staged_objects_readable; on any non-zero commit rc the same probe decides a new blocked_gate value 'staged_objects_missing', beside worktree_head_clobbered and on the same evidence-not-grep discipline — the gate that dies is merely the first one to read the staged diff, so a log grep blames a reviewer that was never the problem. Two falsifications are the point of this note, because both were believed on the way in. (1) The report blamed a concurrent gc. It did not happen: frink's pack .idx files predate the failure by 17 hours, no new pack or .git/gc.log exists, and auto-gc cannot delete a minutes-old object under the default 2.weeks pruneExpire — it moves fresh unreachable objects to a cruft pack. (2) 'The preflight proves the object survived to the gate chain' is FALSE. ship_record_staged_state's write-tree PERSISTS a cache-tree, and write_index_as_tree short-circuits on cache_tree_fully_valid(), which verifies only the TREE objects — so every later write-tree re-reads a cached oid and is blind to a missing blob. Reproduced: stage, write-tree, delete the loose blob, write-tree again -> same oid, exit 0. Both tree-based invariants in assert-staged-set.sh therefore passed straight through the original failure. The probe is built on ls-files + cat-file --batch-check for that reason, and skips gitlinks (a submodule commit is absent from the superproject ODB by design). Deliberately NOT ruled yet: the deletion mechanism. Two candidates remain live — a genuine deletion, or ship and the gates reading DIFFERENT object databases (ship inherits the caller's environment; gates are spawned through __dk_no_git_env, which strips GIT_OBJECT_DIRECTORY / GIT_ALTERNATE_OBJECT_DIRECTORIES). The probe records both views so the next occurrence names its own cause instead of costing another investigation; the durable fix waits on that evidence. gc.auto=0 is added to the gated commit as hygiene only, not as the fix.
