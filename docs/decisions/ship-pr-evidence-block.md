# ship-pr-evidence-block

## Target · 2026-10-10 — devkit ship writes captured red/green regression evidence into a devkit-owned PR-body block

**Context:** devkit PR proof was agent-written prose. 78 of the last 150 merged devkit PR bodies had a Proof section, and only 1 mentioned devkit prove-regression. Nothing machine-written and tied to a commit recorded that a PR's tests fail without the change and pass with it. A deterministic merge verdict therefore had nothing it could trust, and an auto-merge step would rest on prose. Peers show the cost of getting the evidence wrong: 15 of robobun's 127 red/green blocks (oven-sh/bun) counted a build failure as red, and skips were tolerated as green.
**Ruling:** After the PR exists, devkit ship captures red against green with prove-regression and writes the outcome between <!-- devkit:evidence:begin --> and <!-- devkit:evidence:end --> in the PR body. Red is the PR base plus the PR's added or changed test files and supportPaths files, built as an unreferenced commit with a temporary index. Green is the PR head. The step is opt-in through guard.config.json evidence, which holds the consumer's own argv with {files} and {report} placeholders plus support globs. It is bounded by evidence.timeoutSeconds, with an outer 60 s supervisor and a fallback publication. It runs after the branch and receipt refs are settled and never changes ship's exit code. The block records the head and base SHAs, the argv, both runs with their counts, and an outcome from a fixed vocabulary: captured, inconclusive, or not-run with a closed abstention reason. It also reserves a verdict line. Readers treat the block as stale when the PR head differs. Caller-authored text owns every byte outside the block: an explicit --body keeps the current block, and a block pasted into a caller body is dropped.
**Consequences:**
- Positive: Each devkit-shipped PR that changes tests carries machine-written evidence tied to the exact head and base it was produced at. A merge verdict can read that evidence without trusting prose. Consumers that do not configure evidence see no body change and no extra gh calls.
- Negative: Ships whose diff changes tests take longer, and they hold their queue slot meanwhile. A K=1 probe over the 10 most recent devkit main commits that change tests and source measured 13 to 210 s per capture (median about 27 s, all captured). Hence timeoutSeconds 300 for devkit, and up to timeoutSeconds + 60 s plus a 60 s fallback in the worst case. Evidence runs on the shipping checkout's installed dependencies, not an install from the PR head. A PR whose new test imports a module the same PR adds reads inconclusive, because red fails to load. The block is not tamper-evident: anyone who can edit the PR body can rewrite it, so a merge verdict must not treat it as its only authority.
**Vision-fit:** n/a — internal developer tooling; it is the evidence input for evidence-backed auto-merge of devkit-shipped PRs.
**Researched:** SWE-bench builds its red side the same way: the base plus the test patch (swebench/collect/utils.py). robobun's oven-sh/bun evidence blocks and verdicts. qavis's fenced PR-body upsert (<!-- qavis:start/end -->). Vitest 5.0.3 JSON reporter shapes for load, hook and skip failures. arXiv 2607.19843, which shows fail-to-pass can hold when a co-generated test and fix are both wrong, so the block claims captured runs, not proof. The K=1 probe above.
**Rejected:** (a) A sticky PR comment or a commit status. Either avoids sharing the body with caller text, and a commit status binds to the SHA natively. Both split the surface the merge verdict reads, and check runs also need a GitHub App. (b) A prove-regression --overlay option. Ship is the only caller without an explicit red ref, so the overlay stays in ship. (c) Running before gh pr create. That delays the PR and widens the window between the push and the reconcile-manifest write. (d) Porting qavis's edit-history audit. It only detects lost updates and costs a GraphQL round trip; ship instead refuses to publish once the PR head moves. (e) Writing a not-configured block into every consumer PR. That changes the bodies of repositories that never opted in.
**Anchored-bet:** [BET]
**Revisit-when:** A merge step needs tamper-evident evidence (move it to a commit status or check run), or the shadow measurement shows more than half of test-changing devkit PRs reading inconclusive.
**Scope:** cli/lib/ship/evidence/**,cli/lib/ship/publish-evidence.sh

## Target · 2026-10-23 — The evidence block also carries the agent's QA capture, attached by ship through gh --attach

**Context:** The block held only red/green test runs. For UI work the owner's complaint was that PR screenshots prove the UI exists, not that it works (benord-labs/frink#580), and agents now record their change working with devkit machine run. gh 2.99 added --attach (uploads images and video to github.com/user-attachments, rewriting ![…](./file) refs in place; a bare video URL plays inline), so ship can attach that recording itself instead of trusting an agent to paste it.
**Ruling:** After the PR exists, devkit ship captures red against green with prove-regression and writes the outcome between <!-- devkit:evidence:begin --> and <!-- devkit:evidence:end --> in the PR body. Red is the PR base plus the PR's added or changed test files and supportPaths files, built as an unreferenced commit with a temporary index. Green is the PR head. That step is opt-in through guard.config.json evidence, which holds the consumer's own argv with {files} and {report} placeholders plus support globs, bounded by evidence.timeoutSeconds with an outer 60 s supervisor and a fallback publication. The block records the head and base SHAs, the argv, both runs with their counts, and an outcome from a fixed vocabulary: captured, inconclusive, or not-run with a closed abstention reason, plus a verdict line; readers treat it as stale when the PR head differs. After it, a separate QA-capture step (its own 600 s supervisor, regardless of the regression budget) reads the source checkout's devkit machine manifest and attaches the apt capture inside the same block, between <!-- devkit:evidence:qa:begin/end -->: each passing flow's video and final screenshot, else up to 4 screenshots; never a failed flow, a file over 9 MB video / 10 MB image / 6 files, a capture whose working-tree hash differs from the shipped commit at any path the PR changes, or a capture already attached to another PR (uploads.json beside the manifest); each exclusion is named. One gh pr edit --attach call uploads the new files from a staging dir (gh 2.102 resolves ./ refs from its working directory); the section is then settled from what GitHub holds, so a failed upload is named and never retried, and a re-ship reuses the URLs already in the body. A repo with no evidence config gets a block holding only that section, with no regression heading or verdict line. Every re-render of the regression block carries the QA section across. Neither step changes ship's exit code, and media is not a merge-verdict input. Caller-authored text owns every byte outside the block: an explicit --body keeps the current block, and a block pasted into a caller body is dropped.
**Consequences:**
- Positive: A UI PR carries a recording of the real app working, attached by ship, tied to the code it ran and to one PR, in the one body surface a merge verdict reads. Consumers with no machine capture see no change.
- Negative: An upload is irreversible, so anything on the recorded screen reaches GitHub (fresh profiles and fake seed data are the only protection until sc-8001). The QA step needs gh 2.99 or newer and a user token (GITHUB_TOKEN cannot upload), and it adds up to 600 s to a ship that uploads. A flow re-run is required after the last edit, or the capture is left out as different code. The block now holds a second, separately written section, so its two writers must keep carrying each other.
**Vision-fit:** n/a — internal developer tooling; it is the evidence input for evidence-backed auto-merge of devkit-shipped PRs.
**Researched:** gh 2.102 --attach probed on a private scratch PR (norvalbv/devkit-attach-probe#1): ![…](./x.png) is rewritten in place, ![…](./x.webm) becomes a bare URL rendered as <video controls>, an unmatched file is appended at the end of the body, and refs resolve from gh's working directory, not the --body-file directory. cli/cli internal/attachments/references.go. Cursor cloud agents' artifacts dir and RecordScreen tool (REA of Cursor.app 3.24.18). A 7-lens research pass, a 6-seat design room and a feature-critique.
**Rejected:** (a) A sticky PR comment for media: splits the surface the merge verdict reads. (b) A sibling devkit:qa block outside the evidence block: a second owned region in caller text needing its own carry and pasted-copy rules. (c) gh pr create --attach: appends outside the block. (d) Uploading every passed capture: a capture of an earlier or later code state, or one made for another PR, would go up as proof of this one. (e) Retrying a failed upload: duplicates are irreversible.

**Revisit-when:** A merge step needs tamper-evident evidence (move it to a commit status or check run), the shadow measurement shows more than half of test-changing devkit PRs reading inconclusive, or gh changes how --attach resolves refs.
