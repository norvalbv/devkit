# ci-emits-per-file-test-results

## Target · 2026-08-29 — CI emits the per-file test result; the oracle reads an artifact, never a log

**Context:** sc-2245. devkit's gate has been red on main continuously (sc-1896, still open): the last 8 main runs all conclude failure, and on the most recent every step passes except Tests (267 files passed, 4 failed). So 'is CI green' is not a usable oracle — it always answers no and says nothing about the file in hand. Establishing that ONE file was already broken took four gh calls and three differently-shaped greps, ending on 'gh run view --log | grep -c <file>' to prove a negative. That workaround is not merely tedious, it is unsound: this repo runs vitest inside vitest (gate-engine/coverage/__tests__/produce.test.mts spawns a real child), so a 727KB log carries a second 'Test Files 1 failed' summary no grep can attribute. gate.yml's Tests step was a bare 'bun run test:run' with no reporter and no artifact — gh api reports total_count 0 artifacts on every run — so CI knew the per-file answer and discarded it.
**Ruling:** Fix the PRODUCER, not the reader. 'devkit test-report-run' runs vitest with default + github-actions + json reporters and emits two artifacts: the full report and a few-KB per-file summary, uploaded separately with if: always(). 'devkit baseline-status' answers from the summary and NEVER parses log text. It reports runStatus (the whole run) separately from testsStatus (the test step), because a red run whose tests passed is devkit's actual steady state. Per-file answers split into passed/failed/skipped/excluded/absent/unknown; gh is a SOFT dependency degrading to a named unknown per the detectMerged precedent in cli/lib/reconcile.mts. The cache keys on runId+attempt, never on the commit sha. lastPassed is forward-facing: it reports no-artifact-history rather than implying a file never passed.
**Consequences:**
- Positive: An agent separates 'my diff broke this' from 'this was already broken' in one call against structured data, so a persistently red gate stops taxing every verification claim. Because runStatus and testsStatus are separate fields, the state devkit is actually in — red run, green file — is expressible for the first time. Three reporters rather than one means the machine channel is added without removing the human console summary or the PR annotations.
- Negative: History starts empty: no run predating this carries an artifact, so lastPassed returns null for every file until the window fills. Accepted deliberately over backfilling from check-run annotations, which were measured lossy — on run 33260495533 they cover 2 of 4 failing files (10 annotations against 18 failed tests), so ship-branch-resume-scope and judge-tamper would have been reported as passing. A fabricated green is worse than no oracle. Also accepted: a run killed before the reporter flushes leaves no artifact, which is precisely the run an agent most wants explained; it reports as a named absence rather than an empty summary.
**Vision-fit:** n/a — internal dev/CI tooling.
**Researched:** Verified against live data rather than assumed: gh run list on main (8/8 failure), the step-level breakdown of run 33260495533, its artifact count (0), its check-run annotations (11, covering 2 of 4 failing files), and the 727KB log's nested-run contamination. vitest's reporter docs confirm --reporter REPLACES the set and that multi-reporter output needs the --outputFile.json map form. A feature-critique panel returned RETHINK and its findings are folded in: run selection on conclusion rather than status, cache on attempt rather than sha, path relativisation, and the not-run split.
**Rejected:** (a) Scrape the CI log — REJECTED: nested vitest runs make occurrence counting unsound, which is how this problem was being 'solved'. (b) Backfill lastPassed from check-run annotations — REJECTED: measurably lossy, and the failure mode is a fabricated green. (c) 'Just run vitest <file> locally on a clean main checkout' — REJECTED: the failures are 'fatal: empty ident name', which reproduces only where no git identity is configured, i.e. never on a developer machine; a local run reports green while CI reports red. (d) One combined artifact — REJECTED: a walk-back would then fetch the multi-MB report per run, costing more than the log scraping it replaces. (e) Select runs on status == completed — REJECTED: cancelled, timed_out and startup_failure are all 'completed' and carry no report, so one cancelled push run would blank an answerable question.
**Revisit-when:** The default branch is green often enough that per-file decomposition stops being the common path, or a runner other than vitest needs to emit the summary shape (which is deliberately runner-agnostic, unlike the producer).
