# typescript-source-prebuilt-mjs

## Target · 2026-07-05 — TypeScript source, shipped as prebuilt .mjs

**Context:** devkit shipped raw JSDoc-typed .mjs under a no-build, what-you-install-is-what-runs contract. As the codebase grew to ~15k LOC across 148 files, that type layer was near-vacuous: tsconfig ran strict:false and only ~40/148 files carried any JSDoc, so tsc caught almost nothing and refactors + new-contributor changes landed with no type guardrail; the JSDoc that existed was dead weight (TypeScript ignores @param types in .ts). Simply renaming to .ts was blocked because Node refuses to execute TypeScript from a node_modules path and devkit runs from the consumer node_modules (the W-3 invariant), so raw-.ts source would break every consumer gate run under node.
**Ruling:** Author cli/ + gate-engine/ as strict TypeScript (.mts). Dev runs the .mts source directly via Node 23.6+ type-stripping / bun, with no build in the dev loop. devkit release compiles .mts to .mjs into a self-contained dist/ (tsc + an asset-copy of every non-TS file) and commits that dist ON the release commit only (gitignored on working branches), behind a non-bypassable node smoke gate that runs the built bin first. Consumers keep bun add git+https#tag and receive prebuilt .mjs. Every self-referential module path carries a SELF_EXT idiom (derived from import.meta.url) because tsc rewrites import specifiers but not string-literal paths.
**Consequences:**
- Positive: Full strict type safety over 15k LOC (tsc --strict 0 errors, inline types, import-type, discriminated unions, real refactor + onboarding guardrails) with zero consumer-facing change: the install command, the git-URL source, and running .mjs straight from node_modules are all unchanged, and nothing compiles on the consumer machine.
- Negative: The no-build, no-dist property devkit advertised is gone: there is now a maintainer-side build and a generated dist/ committed onto every release tag (build artifacts in git history on tags). Dev + release require Node >=23.6. Every spawn / new-URL / packageDir path to a devkit-own module must carry SELF_EXT (.mts in dev, .mjs in dist) or it ENOENTs in one context, a permanent authoring tax that the migration own regressions came from.
**Vision-fit:** n/a - internal developer tooling.
**Researched:** web: Node docs (Node refuses TS under node_modules; type-stripping default-on 23.6+; --experimental-transform-types removed in Node 26 so only erasable syntax runs natively) and bun docs (lifecycle/prepare scripts do NOT run for git/github deps unless the consumer allowlists the package in trustedDependencies, off by default). brainstorm: a 4-dimension adversarial critique workflow that killed the first (uncommitted-dist) design.
**Rejected:** (a) keep .mjs + strict checkJs + a shared types.d.ts + expanded JSDoc - REJECTED: zero-build and zero-risk, but not real .ts authoring (write @param import('x').T not x: T) and JSDoc ergonomics do not scale at 15k+ LOC, which fails the actual ask. (b) consumer-side prepare build on git install - NON-VIABLE: bun does not run lifecycle scripts for a git dependency unless the consumer adds devkit to trustedDependencies (default-off), so most installs would get raw .ts and break under node. (c) publish a built tarball to a private npm registry - REJECTED: forces every consumer onto an authenticated scoped registry, changing install from git+https#tag to registry auth.
**Anchored-bet:** [BET]
**Revisit-when:** Node ships stable execution of TypeScript from inside node_modules (removing the need to compile at all), OR devkit moves to a published registry package (build-at-publish replaces the committed dist).
**Scope:** cli/commands/release.mts,scripts/copy-dist-assets.mjs,tsconfig.build.json,package.json
**Source:** web · https://nodejs.org/api/typescript.html

## Target · 2026-07-26 — Required new dist artifacts ship with their source

**Context:** The release-only dist policy hid newly generated ignored files from normal status and ship discovery. Three independent source changes landed without their required artifact; a later rebuild then rewrote tracked importers to reference files absent from the package, putting every installed consumer gate at risk of failing before it could run.
**Ruling:** Keep ordinary regenerated dist changes release-only, but ship each newly generated dist artifact in the feature change that first makes tracked output depend on it. Devkit self-host ship and reship fail before worktree creation when physical dist files are untracked, newly added dist paths are unbriefed, or tracked relative imports are unresolved.
**Consequences:**
- Positive: The introducing change owns every new runtime file it requires, so later rebuilds cannot reveal a delayed missing-module failure and release tags retain a self-contained package.
- Negative: A feature PR that introduces a module now carries its narrow generated artifact and must brief that path explicitly; each self-host ship also pays one local dist, index, and import scan.
**Vision-fit:** n/a — internal devkit release reliability
**Researched:** Shortcut sc-1246 evidence from three independent omissions; current ship worktree and release implementation.
**Rejected:** Release smoke only — it executes the CLI entrypoint and missed guard-dup relative imports. Doctor warning only — it does not block the publish path. Commit all regenerated dist on every feature PR — it adds broad generated churn unrelated to the new runtime file.
**Anchored-bet:** [VALIDATED]
**Revisit-when:** The package moves to a registry build-at-publish pipeline that constructs and verifies dist from source without committing generated output.
**Scope:** cli/lib/ship/**,cli/commands/release.mts,scripts/copy-dist-assets.mjs,tsconfig.build.json,package.json
**Source:** shortcut · sc-1246
**Evidence-change:** Three independent post-ruling omissions showed that release-only bulk staging did not protect newly introduced runtime artifacts from disappearing before the release boundary.
- 2026-08-26 — Ship-briefed paths: the untracked/unresolved preflight predicates are evaluated against what THIS ship will commit, not against the caller's Git index. ship-branch.sh and reship.sh git add -f every briefed path, so briefing a freshly generated dist artifact ships it; requiring it to be pre-staged rejected the artifact devkit release had just built (sc-2060). Carve-out: a briefed path whose deletion the ship stages (ship-branch.sh's sc-1489 skip) is NOT treated as shipping. The import walk follows the same will-ship graph, so a brand-new dist module's own imports are now checked at the ship that introduces it instead of one release later.
- 2026-09-02 — sc-2571 — the ship preflight guards a PATH; the invariant belongs to the TREE. A hand-rolled v0.61.0 release commit (no devkit ship, so no preflight and no telemetry) published a dist whose run-review.mjs, overrides.mjs and evidence/scope.mjs all imported an uncommitted evidence/base-context.mjs, and every package-mode consumer ship then died with ERR_MODULE_NOT_FOUND at the review gate after the deterministic gates had passed. cli/__tests__/dist-tracked-imports.test.mts now asserts the same closure over the COMMITTED tree — index blobs, never the physical build, which between releases is ahead of the last committed one and would both hide real drift and invent absent drift. It shares moduleImportEdges with the preflight so the two cannot disagree about what an edge is, and it runs in test:run: pre-push, CI on every PR and every push to main, and inside devkit release. The invariant no longer depends on which command created the commit.
- 2026-09-02 — The SELF_EXT / dual-extension tax the 2026-07-05 Target names is now mechanically enforced for shipped SHELL, not just TS: cli/__tests__/shipped-shell-dual-ext.test.mts scans every .sh copy-dist-assets mirrors into dist/ and fails on a quoted .mts path a script runs whose identical .mjs path is not beside the call site. Forced by #547 — bounded_remote_git in ship-branch.sh was the single omitted site of ~10 and every packaged consumer ship died at the remote check behind a message naming ls-remote. The shipped-file enumerator moved to scripts/shipped-assets.mjs so the scanned set is the build's own set and cannot drift; the test carries a pre-#547 fixture so a passing scan cannot go vacuous. Shell emitted from cli/lib/husky/*.mts template literals stays unscanned (its .mts mentions in comments, regexes and the self-host transform would need suppressions).
- 2026-09-04 — sc-2522 — the dist walk now follows SHELL source edges, not only ESM imports. inspectDistIntegrity seeded its queue from .mjs alone, so a shipped .sh that sources a NEW sibling had no dist counterpart demanded; PR #540's patch-anchor.sh reached ship attempt 7 with only a non-deterministic LLM reviewer standing between it and a published package whose devkit ship cannot start. cli/lib/ship/dist-integrity.mts gains shellSourceEdges, sharing the ImportEdge shape and the unreadable-BLOCKS contract with moduleImportEdges so the two enforcement points cannot disagree about what an edge is. Per the 2026-09-02 sc-2571 note the TREE is primary: cli/__tests__/dist-tracked-imports.test.mts walks all 32 tracked dist .sh over index blobs (agents-hooks included — narrowing it would make one file broad for .mjs and narrow for .sh, and would diverge from the preflight, where briefing a dist/agents-hooks path seeds the queue verbatim) and pins BOTH the file and the edge count, because a broken extractor returns [] everywhere and reads green forever. No external tool was adopted: shellcheck -x -P SCRIPTDIR does resolve all 50 devkit call sites and can be driven to exit 1, but it answers 'does this file exist on disk' and copy-dist-assets mirrors every .sh, so it is GREEN on precisely the #540 bug — the failing predicate is git commit membership, which no bash tool models (same for shfmt, bashate, bash -n, resholve). The tokenizer is reused, not written: hook-gate-scan.mts already had logicalLines/stripComment/splitStatements/words, and gained commandWords (words minus the assignment prefix) because both exec bash dispatches are spelled DEVKIT_SHIP_RESUME_DISPATCHED=1 exec bash ..., which a words[0] test misses entirely. An operand resolves only when its leading expansion is PROVABLY the script's own directory — the inline dirname BASH_SOURCE[0] form, or a variable this file assigns from that idiom or the $0 spelling the agent hooks use; any other expansion is a hole, so a future source of $ROOT/x.sh cannot be silently resolved to a path that means nothing. Honest limit: if a ship adds a.sh sourcing b.sh and NEITHER was built into dist/, the walk never starts (the seed is skipped as absent from physicalSet) and nothing is reported — true for .mjs today too. Also uncovered: .sh entrypoints spawned from .mts (release.mts, review.mts, husky/self-host.mts, install/gitignore-cache.mts).
- 2026-09-04 — **Scope:** cli/lib/ship/**,cli/__tests__/dist-tracked-imports.test.mts,cli/__tests__/shipped-shell-dual-ext.test.mts,cli/commands/release.mts,scripts/copy-dist-assets.mjs,tsconfig.build.json,package.json — The 2026-09-02 sc-2571 note moved this invariant off the ship path and onto the committed tree, but the glob still armed the alignment gate only on cli/lib/ship/**. A change weakening or deleting dist-tracked-imports.test.mts — the enforcement point that ruling designates, and the one a hand-rolled release commit cannot bypass — passed the gate silently. shipped-shell-dual-ext.test.mts guards the same tree for the dual-extension tax.
- 2026-09-04 — sc-2522 follow-up — the shell walk now uses a REAL bash parser (unbash), reversing the hand-roll call in the note above. That note argued no external tool helps, and for the RESOLUTION half it still holds: shellcheck answers on-disk presence and copy-dist-assets mirrors every .sh, so it stays green on the #540 bug. But it conflated resolution with EXTRACTION. Extraction is 'which words are in command position in bash', and that is a parser problem. Evidence: seven review rounds produced escalation-confirmed defects in the hand-rolled extractor, every one a distinct valid-bash shape it misread — exec bash -x / --noprofile (dropped the script), AND-OR lists, if/then/while compound commands, case arms including spaced alternation, one-line function bodies, background lists, command/builtin prefixes, command and process substitutions, a quoted paren closing a substitution early, and a false POSITIVE on an escaped paren. Most were fail-OPEN, which is the direction that matters: an omitted sibling passing as clean. The corpus is only 50 edges, but the guard has to be right about bash it has never seen, and a word-level heuristic cannot be. unbash is 344 KB, zero dependencies, pure JS, error-tolerant, and already the parser knip uses; it is dynamically imported exactly as es-module-lexer is, so consumers short-circuit before paying for it, and it sits in dependencies for the same reason es-module-lexer does — the ESM half already had a parser dependency, and the shell half now has the symmetric one. One walk over the parsed tree collects both the script-dir assignments and the directive operands. The tree is materialised with a JSON round-trip first, because unbash exposes nested `parts`/`script` through non-enumerable getters that a generic key walk silently skips — the bug that made command substitutions look clean. Cost: 451ms for all 32 tracked dist .sh, 27ms for the 99KB ship-branch.sh. hook-gate-scan.mts is left untouched; the earlier commandWords/andOrSegments detour is reverted.
- 2026-09-04 — sc-2522 correction — the note above says hook-gate-scan.mts is left untouched. That is no longer true and the record should not misstate where the parsing lives. The unbash walk, the script-dir idiom regex and the bash-option handling now sit in cli/lib/doctor/hook-gate-scan.mts, exported as scanShellScript/ownDirVars/assignedNames; cli/lib/ship/dist-integrity.mts keeps only the resolution half — expansion stripping, the dist-relative join and the ImportEdge shape. The split is deliberate on two counts: hook-gate-scan is already this repo's shell-shape module, and dist-integrity had reached the 500-line cap with cli/lib/ship at its 12/12 fan-out, so a new file beside it was not available. Reviewers then closed three further fail-open paths that only a scope model catches: a `bash -c` child's assignments must not vouch for its parent NOR inherit from it (any directive inside one is a hole), only a TOP-LEVEL assignment is trusted because a function-local or branch-local one may never run, and a name this script assigns is never treated as an inherited external root — `HOME="$SCRIPT_DIR"` is not $HOME.
- 2026-09-04 — sc-2522 scope model — the shell walk reasons about a script's TOP-LEVEL sequence only, and that boundary is deliberate and symmetric. An assignment certifies a directive only when it is top-level and nearest-preceding; a mutation withdraws that certification only under the same rule. So `eval`, and the builtins that write a variable with no Assignment node (printf -v, read, declare, typeset, local, export, mapfile, readarray, getopts, unset), untrust their targets at top level — with a `*` wildcard when the target is itself an expansion, as `printf -v "$x"` is. `env -S` is a hole outright: its argument is a whole command line this cannot see into. The documented LIMIT: a function that rewrites SCRIPT_DIR, called before a top-level directive, is not modelled. Making nested mutations invalidate would be the fail-closed choice, but review-target.sh does `printf -v "$variable"` inside a function at line 133 and sources a sibling at 191, so a global rule turns devkit's own tree red. Closing that needs real dataflow analysis, which is a bigger piece of work than this guard; the honest position is that this catches the omission class sc-1199/sc-1246/#540 are about — a NEW sibling nobody briefed — not an adversarially obfuscated one. Every shape a reviewer demonstrated is covered by a named test in cli/__tests__/dist-integrity-shell.test.mts.
