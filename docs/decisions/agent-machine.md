# agent-machine

## Target · 2026-10-23 — devkit machine gives the agent in a worktree a leased slot on this Mac: a 10-port block at

**Context:** Many agent sessions on one Mac drive the same apps at once. They collided on fixed ports (claude-usage-dashboard's next dev -p 8788 is also the live hub, sc-7612), on one shared Chrome that every chrome-devtools MCP session autoConnects to (95e085fe new_page timeouts, foreign tabs), on shared app data and daemons (b80cd01b), and on each other's processes (sc-2331). PR evidence for UI work was headless screenshots of components with fixture data that proved the UI exists, not that the feature works (benord-labs/frink#580: 'Not tried by hand: a real export and import ... in the running app'). The owner asked for Grok Bot style own machines for screenshots and video.
**Ruling:** devkit machine gives the agent in a worktree a leased slot on this Mac: a 10-port block at 40000+10n (get-port probes every local host), its own headless Chromium profile, its own app-data dir, its own process group and its own evidence dir under the worktree's git dir. Slots live under <passwd home>/.devkit/machines behind one machine-wide process lock (gate-engine/judge/process/process-lock), one per worktree, default cap 3 (owner config.json {slots}), reaped by the next up anywhere when its worktree is gone or no devkit machine command touched it for 30 minutes (an agent's own up reuses its lease first); up refuses at macOS memory pressure level 4, waits for the app to answer HTTP, starts it without ship's DEVKIT_* env or a host app's run mode, and signals a group only while its recorded leader identity still holds. devkit machine run executes the agent's asserted Playwright flow (playwright-core pinned exactly, 1.63.0, its own headless shell) while recording the whole flow as video plus named screenshots, and lists them in manifest.json with pass/fail, HEAD and a working-tree hash; clear deletes them. Web apps only. The recipe (guard.config.json machine: command, seed) holds no env, because that file may be committed: an app variable goes in the argv through env(1), secrets stay in the caller's environment, and a recipe with env is refused with that remedy. It is opt-in tooling the agent invokes, never a gate: no generated hook calls it and it never changes a commit or ship exit code.
**Consequences:**
- Positive: Two worktrees never share a port, browser, cookie jar, process or data dir, and each one's video shows only its own app, so concurrent UI work stops colliding. The proof for a UI change becomes an asserted run of the real app with a recording a reviewer can watch, instead of a static screenshot.
- Negative: Isolation is per worktree, not per agent: agents sharing one checkout share its machine. Not a VM and not a security boundary: every slot runs as the owner with their files, keychain and network; CPU and RAM are shared, so a loaded Mac still slows every slot; CDP frames never show native OS dialogs, menus or the keychain, which a flow must stub and say so; real singletons (the live hub, quotas) still need their own leases. Electron apps (frink) are not served yet: their isolation needs the app's own recipe (FRINK_HOME, seed, fake claude) and frink is a public repo. Adds playwright-core (13.45 MB, no dependencies) and get-port (14 KB) to every devkit install and a 195 MB headless-shell download where it is not cached. The consumer must declare how to start its app (guard.config.json machine). An agent that goes 30 minutes without a devkit machine command loses its slot to the next up and re-runs up.
**Vision-fit:** n/a — internal tooling
**Researched:** 7-lens research workflow plus a 6-seat opus design room (swarm-235212-ozkw, 6/6 incl. verifier) and a feature-critique pass: ~80 collision reports in 11 classes, most needing namespacing not VMs; REA of Cursor.app 3.24.18 (Docker in Firecracker per agent, ffmpeg x11grab, artifacts dir) and of Grok Bot.app 0.75.0 (one box per user, each bot its own screen plus a lease, docs.x.ai/grok-bot/computer-and-apps); Apple's 2-macOS-VM licence cap; Playwright page.screencast recorded web and Electron 44 locally; a macOS bind probe showed a 127.0.0.1-only check reads a port held on 0.0.0.0 as free; arXiv 2610.29609 and 2607.25904 (screenshots alone are weak completion evidence).
**Rejected:** (a) A Linux microVM or container per agent (Apple container, Docker sbx, Docker Desktop): +0.3-0.5 GB per guest on a host with under 1 GB free, no inotify across the mount, a cold guest repeats Qavis's boot failures, and frink's QA rig is macOS-only. (b) A macOS VM per agent (Tart, Lume, UTM): capped at 2 by Apple's licence and Virtualization.framework. (c) An off-host runner per PR: Qavis's failed shape (237/238 runs could_not_run) and inline uploads need a stored user token. (d) chrome-devtools-mcp --isolated alone: fixes the shared browser but not ports, data or processes, and it is the owner's Frink config, not devkit's. (e) Electron via _electron.launch with only --user-data-dir: bypasses frink's FRINK_HOME, seed and fake-claude isolation and could put the owner's data in a public PR.
**Anchored-bet:** [BET]
**Revisit-when:** A flow that matters needs native OS surfaces (dialogs, menus, keychain) captured for real, an Electron consumer ships a slot-aware boot recipe, the host gains enough memory to run a microVM per agent, or a slot collision is observed despite the lease.

## Target · 2026-10-24 — guard.config.json machine.mode picks light (the default, unchanged) or full

**Context:** Light mode (a headless Chromium profile per worktree) cannot QA what is not a web page: Electron and other desktop apps, native menus and browser dialogs, multi-window flows. The owner asked for Grok Bot's shape, where each bot gets its own screen on a shared computer and can run any app. Not every repo needs that weight, so the choice has to be per repo.
**Ruling:** guard.config.json machine.mode picks light (the default, unchanged) or full; up --full/--light overrides it, and each up brings the slot to its mode (a light up removes the slot's box). Full mode keeps the slot lease and gives it a box: one container per slot in Docker Desktop's single Linux VM, from a devkit-built image (Debian, Xvfb :1 at 1280x800, xfce, Chromium with --no-sandbox --test-type, x11vnc behind a per-box random password, noVNC, xdotool, ffmpeg, passwordless sudo) tagged by the hash of its own definition and built on first use. The worktree mounts read-only at /work; the slot's 10-port block is forwarded from the box's 127.0.0.1 to the host so URLs match light mode; the live view and DevTools publish on two more ports of the block, on 127.0.0.1 only. The lease records the box (name, ports, password). No docker call runs under the lease lock: up checks the box before taking it, and down and reap remove the box without waiting. screenshot saves the whole screen, exec runs a command on the desktop, and run drives whatever answers DevTools in the box while ffmpeg records the whole screen (15 fps, yuv420p, faststart, 10-minute cap) into the same manifest, so ship's upload is unchanged. A flow's exec is bounded at 5 minutes. There is no unasserted recording verb: proof is always an asserted run, with exec giving flows xdotool input and desktop state to assert on.
**Consequences:**
- Positive: An agent can QA any Linux app, including Electron and its native menus, on its own desktop, with a recording a reviewer can watch and a live view the human can open; two worktrees never share a screen, browser, filesystem or process, so concurrent QA stops colliding.
- Negative: Full mode needs Docker Desktop running and a one-time image build (144 s cold, 1.9 GB); each box holds about 410 MB idle and about 650 MB while a flow records, inside Docker's VM. devkit now owns a Dockerfile and start script whose base packages drift with Debian. Chromium runs without its sandbox in the box. Like light mode, a box is not a security boundary: boxes share Docker's bridge, so one box can reach another's DevTools, and every box reaches the Mac's loopback ports. Only Docker Desktop was probed for host.docker.internal reaching 127.0.0.1. macOS-native apps still cannot be QA'd, and an Electron app's Linux build and native dependencies are the consumer's to install in the box. Container isolation is weaker than a VM per agent, accepted because Grok Bot itself shares one computer.
**Vision-fit:** n/a — internal tooling
**Researched:** Probe on this Mac (cold image build 144 s, 1.9 GB; boxes ready in under 2 s, about 410 MB idle and 650 MB while recording; Chromium and Electron 45 driven over CDP and xdotool; Chromium's setuid sandbox crashes in the box; DevTools answers before the window manager maps windows, so box-start waits for it). 7-lens research workflow: cua/Lume (pre-1.0, monthly renames, FSL viewer, no packaged recorder), container desktops (Docker Desktop lower risk; Apple container never returns freed memory, exec skips the IPC namespace), Tart/UTM/Lima VMs per agent (3 GB pulls, no balloon in Tart, unmeasured), drive-anything (Anthropic computer_toolset_20260801; 1280x800 needs no coordinate scaling), apps (keep web servers on the host; Next and Vite host checks), premise (Grok Bot docs: every bot shares one computer, each gets its own screen). feature-critique pass and a 3-seat proof audit: lock budget, view auth, yuv420p, output-side -framerate, schema skew, port drift.
**Rejected:** (a) A VM per agent (Lima, Tart, cua --kind vm): own kernel but 3-5 GB images per clone, no memory balloon in Tart, boot and RAM unmeasured, and Grok Bot itself does not do it. (b) cua as the stack: pre-1.0 with monthly renames, its viewer is FSL, recording is not packaged, telemetry on by default. (c) Several X displays inside one shared container: shares a filesystem and process table between agents, and x11vnc and noVNC ports would need routing per display. (d) An unasserted record start/stop verb: ship would upload a session the agent merely declared passing.
**Anchored-bet:** [BET]
**Revisit-when:** A flow needs macOS-native surfaces captured for real, a consumer runs devkit on a non-Docker-Desktop engine or a Linux host, the box's memory cost blocks three concurrent slots, or a box escape or cross-box interference is observed.
**Scope:** cli/lib/machine/**,cli/commands/machine/**
**Source:** manual
**Evidence-change:** The owner rejected web-only light mode as not emulating Grok Bot: agents must QA Chrome, Electron or any app on their own computer. A probe on this Mac measured a desktop container per slot inside Docker Desktop's one VM at under 2 s to ready and about 330 MB with Chromium, and drove Chromium and an Electron 45 Linux app over CDP and xdotool while ffmpeg recorded the screen. Rejected (a)'s grounds no longer hold: memory pressure is admitted per up, file events are not needed because the app stays on the host, and frink's Linux build already runs under X.
