# benchmarks-grow-from-telemetry

## Target · 2026-08-01 — Benchmarks grow from verdict-labeled telemetry

**Context:** Reviewer corpora hold 13-66 rows per suite while the gates adjudicate real findings daily and discard the evidence; every hand-authored row costs human time, and ~570 banked CodeRabbit findings plus ~12 correctness FAILs/day already carry labels (fix committed vs rebutted/waived). The 2026-08-01 frink methodology addendum (amended at commit) is the charter.
**Ruling:** Corpus rows are minted from verdict-labeled telemetry: diff-bytes archive on reviewer FAIL (enabler, ships in the first PR of the effort), guard-review waive with rationale (decoy mint), collector attempt-correlation (gold mint), and CodeRabbit thread mining via the GitHub API with the collector scope-confirmation join (pr_comments lacks path/threading/resolution). Humans do disagreement-triage only, never authoring.
**Consequences:**
- Positive: Labeled-row throughput replaces authoring as the growth mechanism; clean-pass and recall move onto defensible sample sizes (the correctness precision question needs ~120 decoys); benchmark and gate cannot drift because bench.mts keeps driving the real runCascade.
- Negative: Mined gold measures localized-fixture precision and RELATIVE recall only — absolute recall requires known-answer imports (c-CRAB/CR-Bench); mined labels carry noise (bot-compliant LLM authors), so kappa relabel + noise floor are preconditions for any delta-based decision; fixture trimming places rows far below production input size, quantified via a calibration slice.
**Vision-fit:** n/a — internal tooling
**Revisit-when:** The capture points produce fewer than ~10 usable rows/month, or the calibration slice shows localized-fixture recall diverges from full-context recall by more than 15pp

## Target · 2026-09-05 — Mine source cases and validate derived repair controls

**Context:** The September correctness rebaseline showed that repair twins account for almost all false blocks: 25/26 on September 4 and 27/30 after the September 5 holdout reset. No existing row activated the shipped cap-400 chunk plan. The August telemetry-only wording does not explicitly describe the source-anchored repair adaptation already present in the runbook; sc-2500 now requests large fix-pairs without adding gold rows. Requiring an independently observed clean telemetry event for every repair would prevent measuring the same defect before and after its correction.
**Ruling:** Keep verdict-labeled telemetry and fix-anchored known-answer imports as the roots of corpus cases. Agents may derive repaired PASS siblings from an existing source-anchored gold, explicitly marked adapted with variantOf, shared caseId and preserved original source references; these are executable repair controls, never represented as independently observed telemetry. The same invariant must pass in the base and repair and reproduce in the buggy postimage, with assertions outside judge-visible files. Larger adapted contexts must be coherent executable code with resolved dependencies and actual native chunk coverage, not padding. Shared contexts remain one transitive holdout family. Do not mint unanchored gold labels from an agent claim or a fabricated example; sc-2500 adds no gold rows. Human effort remains disagreement-triage. Freeze and remeasure the changed corpus and runner, declare the epoch boundary, retain the label-noise bound, and interpret exposed adaptations as regression evidence rather than unseen production ground truth.
**Consequences:**
- Positive: Allows the corpus to test whether the reviewer distinguishes an observed defect from its executable repair at production input sizes while retaining auditable source lineage and family-level holdout integrity.
- Negative: Repair outcomes and expanded contexts are controlled adaptations, not independent production observations. Controls establish their tested invariants but do not certify all clean labels; correlated families, exposed cases and the existing 13.9% noise bound limit inference. Larger native plans also cost more judge calls.
