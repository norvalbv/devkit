# correctness-lens-hole-instrument

## Target · 2026-09-02 — Lens holes are measured by a partitioned second-detector cross-tab before any lens is added

**Context:** devkit's correctness reviewer has exactly four lenses and had no instrument to tell whether a real-world bug class falls outside all four: coverage was only ever measured against the lenses' own gold counts (28/19/18/10), which is circular, so 'do we need a fifth lens' was argued from a 5-instance anecdote (the vacuous-success family) while a fifth lens costs roughly +25% judge spend on the highest-volume reviewer (3,105 commit_reviews rows) and would launch with zero corpus rows to evaluate it. The 2026-08-31 bench-validity research found that every lens claim across four research lanes was rhetoric, not measurement, and that truncation (60 KB evidence cap) and scope are the competing explanations for any apparent hole that nobody had separated out.
**Ruling:** Lens holes are MEASURED before any lens is added, with one reusable reducer (external/holes.mts): a second detector's labelled findings are joined to what the correctness reviewer held in scope, saw in full, and said on the same change, and every miss is partitioned not-reviewed / not-in-scope / evidence-uncertain / in-evidence-unmatched / matched BEFORE any lens attribution. CodeRabbit categories on devkit's own repos are the primary instrument ($0, 100% marker parse, verification-trace roots dropped); Martian Code Review Bench goldens are a confirmatory external precision/recall probe and a source of miss candidates only. Only in-evidence-unmatched misses feed the lens question; attribution uses a pre-registered rubric (the four brief definitions plus an explicit none) whose light-judge triage must reach kappa >= 0.6 against hand labels before its column counts. A fifth lens is warranted only when a class no existing checklist names holds a clear majority of eligible misses (category denominator >= 8 catchable) across both sources AND a prompt-bullet A/B under the nearest existing lens, run on the re-baselined corpus, fails to recover them. Measurement runs now; the verdict waits for the re-baseline (sc-2494).
**Consequences:**
- Positive: A lens decision rests on a repeatable count table that names its own denominators, not on whichever anecdote was loudest; the same reducer serves any future detector, so a sixth or seventh lens question costs hours rather than a 26-agent research workflow; an instrument that cannot fire says so (ineligible categories are reported, never read as a null result); committed artifacts stay counts-only so third-party file paths and finding text never enter the public repo.
- Negative: Per-file evidence is not recorded (omitted_files and truncated_files are counts), so any omission in an attempt marks every file of that attempt evidence-uncertain and understates the catchable denominator; the path-plus-±10-line match is a proxy for 'the reviewer raised this defect' and can credit a different finding on the same lines; CodeRabbit's taxonomy is a vendor's six coarse categories, and its findings are post-push cumulative-PR findings judged against per-commit staged reviews, so a finding that emerges only from two commits' interaction is invisible to the gate by construction; the human labelling round (~90 findings) is real owner time per detector.
