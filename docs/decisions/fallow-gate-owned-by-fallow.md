# fallow-gate-owned-by-fallow

## Target · 2026-07-25 — devkit wires fallow own hooks; it does not author a fallow gate

**Context:** devkit shipped its own fallow gate plus a 300-line staged-diff re-scoper, built on the belief that stock fallow audit blocks on any finding anywhere in the worktree. That belief was stale: fallow defaults to --gate new-only (only findings the changeset introduces fail) and accepts --diff-file/--diff-stdin for exact scoping. The reimplementation had already DRIFTED from fallow attribution — it treated introduced duplication as blocking where fallow rates it warn — and carried failure modes fallow does not have: an anonymous exit 2 blocked an otherwise-clean scoped ship with no reason surfaced anywhere (sc-1192), on top of 800KB payload suppression, JSON re-parsing, spawn-retry and diagnostics code. Roughly 700 lines of maintenance for behaviour the vendor already owns. Measured against the preserved sc-1192 ship worktree: fallow audit --diff-file staged.diff returned the identical two introduced clone groups in 2.9s, versus a full-worktree audit plus post-filter.
**Ruling:** devkit does not author a fallow gate. devkit init and devkit upgrade wire fallow OWN hooks (fallow hooks install --target git and --target agent), and devkit mirrors the agent hook onto the Cursor surface that fallow installer does not write. devkit owns installation, version pinning and surface coverage; fallow owns detection, attribution and the gate script itself.
**Consequences:**
- Positive: A repo adopting devkit gets fallow maintained gate on every surface devkit supports with no second manual install step, and the gate attribution tracks fallow releases instead of drifting from them.
- Negative: devkit gives up staged-INDEX scoping: fallow stock hook attributes against the merge-base changeset, so in a shared checkout another agent uncommitted work counts as introduced and can block your commit. Acceptable because devkit ship commits inside an ephemeral worktree holding only the briefed paths — there the changeset IS the staged set — and raw git commit in a shared tree is the workflow the protected-branch guard already steers away from. Second cost: fallow regenerates its script on every install, so consumer customisation must live in fallow config, never in the file.
**Vision-fit:** n/a — internal tooling (devkit gate distribution)
**Researched:** fallow 3.6.0 CLI surface (audit --help: --gate new-only is the default, --diff-file and --diff-stdin exist); fallow Claude-hooks integration docs; empirical A/B against the preserved sc-1192 ship worktree where both paths produced identical introduced clone groups.
**Rejected:** (a) Keep devkit own gate plus staged-filter — LOSES ON CORRECTNESS: it reimplements attribution fallow owns and had already diverged (introduced duplication blocking vs fallow warn), so consumers get a verdict fallow itself would not give. (b) Keep the filter but feed it fallow --diff-file output — LOSES ON REDUNDANCY: once the diff scopes the audit, the post-filter has nothing left to attribute. (c) Leave fallow agent hook for the consumer to install by hand — LOSES ON ADOPTION: it is the step consumers forget, and it is precisely why frink hand-patched a copy that then drifted out of sync.
**Anchored-bet:** [BET]
**Revisit-when:** fallow agent hook stops defaulting to --gate new-only, or devkit needs staged-index rather than merge-base attribution outside a ship worktree
**Scope:** cli/lib/install/install-fallow.mts,cli/commands/init.mts,agents-hooks/**
**Source:** web · https://fallow.tools/docs/integrations/claude-hooks/

## Target · 2026-07-25 — devkit owns the SCOPE handed to fallow; fallow owns detection and attribution

**Context:** The prior Target on this axis ruled that devkit should not author a fallow gate at all, and wired fallow's own agent hook instead. That reasoning rested on the ship worktree pinning --base DEVKIT_SHIP_BASE_SHA, and hand-waved the other two paths as workflows the protected-branch guard steers away from. Steering away is not preventing. fallow's stock hook resolves its base as the merge-base against the branch upstream or the remote default, which fails concretely in two ways: (1) the primary consumer's trunk is 0.0.9 with main 186 commits stale, so the changeset would be ~186 commits plus the staged files, flagging all of it as introduced; (2) in the shared checkout devkit exists for, another agent's uncommitted work is inside the changeset and blocks your commit — the original sc-1192 symptom. Neither is reachable by configuration: FALLOW_AUDIT_BASE pins a REF, and the staged set is not a ref range.
**Ruling:** devkit authors a THIN wrapper hook that decides SCOPE only: it captures the staged diff (git diff --cached --binary --full-index --find-renames --relative) and hands it to fallow via --diff-stdin, then gates on fallow's own reported attribution. devkit contributes no detection and no attribution — the 300-line JSON re-scoper stays deleted. fallow's own agent hook is NOT installed (devkit's wrapper replaces it on that surface); fallow's git hook stays as-is.
**Consequences:**
- Positive: A commit is judged on exactly the set going through the commit gate, on every surface and in every repo, regardless of how stale the remote default branch is or what other agents have uncommitted in a shared tree. Whole-graph analysis is retained: --diff-stdin scopes attribution, not the module graph, so dead-code and duplication detection still see the whole project.
- Negative: devkit owns one more script, so a fallow release that changes the audit JSON shape (verdict / attribution counters) can break the gate — the wrapper reads two fields, which is the exposure. Second: verdict alone is not a faithful blockable signal (a duplication-only staged set returns warn, and --gate all does NOT change that), so the wrapper must also read attribution.duplication_introduced — an explicit policy knob devkit now owns and must keep in step with fallow's severity model.
**Vision-fit:** n/a — internal tooling (devkit gate distribution)
**Researched:** feature-critique agent, 2026-07-25: purpose-built two-agent repo against fallow 3.6.0. Verified the base-resolution table above; verified --diff-stdin scopes attribution rather than filtering files; verified the three baseline flags still apply under --diff-stdin and can suppress a genuinely introduced clone group to pass; verified an unknown flag and a config-parse failure both exit 2 (indistinguishable), while an absent binary exits 127.
**Rejected:** (a) Wire fallow's own agent hook unchanged (the prior ruling) — LOSES ON SCOPE: verified to attribute another agent's unstaged work as introduced, and to depend on a remote default branch that is 186 commits stale in the primary consumer. (b) Pin the base via FALLOW_AUDIT_BASE or --base HEAD — LOSES ON EXPRESSIVENESS: verified both still sweep in unstaged work, because a ref range cannot express the index. (c) Restore the deleted staged-filter — LOSES ON CORRECTNESS AND COST: it reimplemented attribution fallow owns, had already drifted from it, and cost ~700 lines to do worse.
**Anchored-bet:** [BET]
**Revisit-when:** fallow ships a first-class staged/index scoping flag (making the wrapper redundant), or its audit JSON drops the attribution counters the gate policy reads
**Scope:** cli/lib/install/install-fallow.mts,cli/commands/init.mts,agents-hooks/**
**Source:** collab · feature-critique 2026-07-25
**Evidence-change:** Empirical test against fallow 3.6.0 (feature-critique, 2026-07-25) refutes the prior tradeoff's premise. Controlled repo, agent A stages a clean file while agent B has unstaged complex/dead code: bare 'fallow audit', 'FALLOW_AUDIT_BASE=HEAD fallow audit' and 'fallow audit --base HEAD' ALL attribute agent B's work as introduced (complexity_introduced 1, dead_code_introduced 2, verdict fail) and block agent A. Only 'git diff --cached | fallow audit --diff-stdin' scopes correctly (0 and 1, agent B excluded). There is therefore NO configuration-only path to staged-set scoping — the prior ruling's assumption that fallow's own hook suffices is false outside a base-pinned ship worktree.

- 2026-07-31 — Fallow 3.7.0 capped `--diff-stdin` at 10 MiB and falls back to whole-project attribution above the cap. A controlled 3.10.0 A/B reproduced the original cross-agent failure: a normal staged diff excluded unstaged debt and passed, while an oversized diff attributed that debt as introduced and failed. The thin wrapper therefore fails open before invoking Fallow when its captured diff exceeds the vendor cap; chunking was rejected because cross-file attribution and duplication are not safely composable across partial audits.
- 2026-08-04 — The wrapper's block channel is exit 2 on the Bash PreToolUse surface, so it sees every shell command an agent runs and a mis-scoped block removes the git reset that would clear it (sc-1338, and its recurrence sc-1417 after the fix shipped to main but missed the v0.47.1 tag). The contract is therefore FAIL-OPEN BY CONSTRUCTION, not completeness: only a segment parsing as a real git ... commit is audited, and malformed hook input, absent tooling, an oversized diff and an unreadable verdict all exit 0. Every classification error must land on the under-firing side — env-assignment prefixes (FOO=1 git commit), wrapper binaries (env/sudo/nohup) and bash -c quoted commits are all inert today and reach fallow's own git hook instead. Measured 2026-08-04 against fallow 3.6.0: with a staged set fallow rates fail, git reset / git restore --staged / git stash / git status / a typecheck all exit 0 without fallow being spawned, while git commit exits 2. Separately measured and worth recording because sc-1417 claimed otherwise: pre-existing dependency debt does NOT drive the verdict — a repo with an unused @anthropic-ai/sdk and a clean one-line staged diff returns verdict=pass with the finding attributed dead_code_inherited under gate=new-only. Those findings appear in a block message only because the block path dumps fallow's whole human report. Known gap: the exit-2 channel is Claude's PreToolUse protocol; Cursor's beforeShellExecution and Codex's response contracts are unverified.
- 2026-09-04 — sc-2526 — the advisory's findings now reach the ship terminus, and the stage stays LAST. Two devkit-side changes; no change to who owns detection. (1) The self-host advisory reads fallow's OWN verdict rather than its exit code. For an ADVISORY the exit code is not the faithful signal it is for the blocking wrapper: measured against fallow 3.10.0, a duplication-only introduced changeset returns verdict=warn, attribution.duplication_introduced=1 and EXIT 0 while still printing the clone group — so an exit-code-derived row is silent on precisely the run whose finding is invisible. It emits advisory_result{gate:'fallow-advisory'} carrying fallow's published introduced counters, which this Target already licenses ('gates on fallow's own reported attribution'); devkit parses no fallow prose and re-scopes nothing. (2) Ordering: the stage stays last. Moving it ahead of guard-review was rejected — the deterministic chain exits ahead of anything it could be moved in front of, so it would still miss most blocked runs, and it would pay fallow's measured ~1.15s on exactly the runs the hook short-circuits, inverting review-gate-in-chain's 'stop paying for a judgement of a diff that is about to change'. What made the findings unreadable was the CHANNEL — prose printed above a success banner — not the position, and the terminus row fixes that wherever the stage sits. VENDOR FACTS, pinned because they forced the two-run shape: fallow 3.10.0 has no single-invocation tee. '--output-file' REPLACES stdout rather than teeing it, and '--sarif-file' (documented as 'in addition to the primary --format output') writes nothing at all on the audit subcommand. So the JSON pass always runs and the HUMAN report re-runs only on a non-clean verdict: ~1.61s expected against ~1.15s before, at a measured 40% firing rate over devkit's last ten commits. A fallow release that fixes --sarif-file would collapse this back to one run.
- 2026-09-04 — **Scope:** cli/lib/install/install-fallow.mts,cli/commands/init.mts,cli/lib/husky/self-host.mts,agents-hooks/** — sc-2526: the recorded Scope missed the file that actually decides the audit's scope. This Target rules that devkit's wrapper hands fallow the SCOPE and nothing else, but the self-host advisory's base pinning, its verdict read and its never-blocking shape all live in cli/lib/husky/self-host.mts's FALLOW_FRAGMENT — outside the glob, so the alignment gate never armed on it. Same blind spot qavis-advisory-gate's 2026-08-26 note wrote up after publish-qavis.sh shipped a caller for a subcommand that did not exist.
- 2026-09-28 — sc-3020 — the OVERLAY's BLOCKING staged checks now run before the AI guards; the 2026-09-04 'stage stays last' ruling is unchanged for what it governed. That ruling was about the self-host ADVISORY, which never blocks, so moving it earlier bought nothing. The overlay fallow gate (cli/lib/husky/husky-block.mts, buildOverlayHook) BLOCKS, and it sat after comments/decisions/review — so an unused export in an overlay consumer surfaced only after the full reviewer chain (the sc-3020 report: one extra ~20-minute ship attempt for a two-word fix). On commit, ship and dry-gates the overlay now emits helpers → deterministic → staged eslint/biome/fallow → AI guards → qavis. The ~1.15s fallow cost is paid on runs about to pay for the reviewer chain anyway, which is review-gate-in-chain's own 'stop paying for a judgement of a diff that is about to change'. Review mode is DIAGNOSTIC and keeps its merge-base baselines after the guards: those baselines exit on a finding, so running them first would hide the reviewer's report. Existing overlay installs keep the old order until devkit doctor --fix or devkit init --overlay regenerates the hook.
- 2026-10-05 — Reclaim of fallow's own agent hook now matches the registration by its script, not by exact command text: any Claude or Cursor handler whose WHOLE command runs only .claude/hooks/fallow-gate.sh or .cursor/hooks/fallow-gate.sh (an optional FALLOW_GATE_COMMIT_ONLY=1 prefix, an optional bash/sh, then the script bare, as ./, or under a double-quoted CLAUDE_PROJECT_DIR) is reported by doctor and stripped by init, whoever wrote it. That widens the reclaim from devkit-written literals to fallow-written registrations, which this Target licenses because devkit's staged wrapper replaces fallow's agent hook. Measured: fallow 3.10.0 'fallow hooks install --target agent' writes "$CLAUDE_PROJECT_DIR"/.claude/hooks/fallow-gate.sh, which matched none of the old literals, so the double gate was invisible to doctor. Only those exact spellings qualify, never a general shell grammar: review found three separate ways a permissive grammar deleted a handler that runs consumer logic or never runs fallow (substitution in an env value, a single-quoted unexpanded dir, an invalid assignment name, BASH_ENV/PATH prefixes that run consumer code first, an unquoted dir that word-splits). Chaining, redirects, malformed quoting, fallow-staged-gate.sh and scripts outside the provider hooks dir never match, because the whole handler is dropped on a match.

## Target · 2026-10-05 — devkit's own pre-commit block carries the staged fallow gate; fallow's git installer is never run

**Context:** Target 2 kept fallow's git hook as-is, but devkit init writes .husky/pre-commit before running fallow hooks install --target git, and fallow refuses any existing hook with exit 2 and prints a paste block scoped by fallow audit --base, a merge-base against the upstream or the literal main. So the install failed on every package and standalone consumer, devkit relayed the paste block, consumers adopted it, and it false-blocked: with no upstream an earlier unpushed commit's finding blocked every later commit, and with no local main every commit failed rc=2. Package and standalone hooks carried no fallow gate of their own, so the paste was their only commit-time path, and baseline saving keyed on the failed wiring never ran.
**Ruling:** Every devkit-owned consumer pre-commit block (package, standalone, overlay) carries one staged fallow gate: the captured git diff --cached handed to fallow audit --diff-stdin. devkit never runs fallow's git hook installer. The gate blocks only on fallow's fail verdict (exit 1). An absent fallow or an empty staged diff skips the audit silently, as overlay always has; a diff over fallow's 10 MiB --diff-stdin cap and any fallow error (exit 2 or higher) skip it with a printed line. Package and standalone init write no fallow-baselines/. devkit doctor reports a selected fallow gate missing from the block as fixable drift. Self-host keeps its advisory-only fragment.
**Consequences:**
- Positive: A consumer who selects fallow gets a commit gate judged on exactly the staged set, in every install mode, with no manual paste step; findings from earlier commits, a missing main branch, or a zero-commit repo never block a commit.
- Negative: devkit owns the gate script on the commit surface too, so a fallow release that changes its exit-code contract or the --diff-stdin cap can mis-gate. Treating exit 2 as fail-open means a broken fallow config passes commits apart from one printed line. A duplication-only changeset (verdict warn, exit 0) does not block, unlike the agent wrapper, which reads attribution. Existing consumers with fallow selected see hook drift until devkit upgrade or doctor --fix regenerates the block, which turns on a blocking gate they selected but never received. A fallow audit --base block a consumer already pasted outside the managed block keeps running until they delete it; devkit does not detect it, because no bounded shell matcher classified wrapped, chained and function-scoped calls without both misses and false reports.
**Vision-fit:** n/a — internal tooling (devkit gate distribution)
**Researched:** Measured on fallow 3.10.0 in temp repos: --force overwrites the whole hook and stays merge-base scoped; --branch only changes the fallback literal. git diff --cached piped to fallow audit --diff-stdin passes an unrelated staged file over an earlier commit's dead file (rc=0) where fallow audit --base main returns rc=2, and blocks a newly staged dead file (rc=1). --diff-stdin still needs a detectable base: a zero-commit repo and a trunk-only repo with no remote return rc=2. Above 10485760 bytes fallow disables line filtering and reports inherited findings (rc=1). fallow-baselines/ changes no verdict without explicit --*-baseline flags (identical present, corrupt, absent) and with them suppresses a genuinely introduced finding. fallow-rs/fallow crates/cli/src/init.rs at v3.31.0 has no append or managed-block mode; fallow issue 242 shows the paste block is intentional.
**Rejected:** (a) fallow hooks install --force: overwrites devkit's whole hook and stays merge-base scoped. (b) --branch HEAD: changes only the no-upstream fallback, still a ref range that cannot express the index. (c) Keep relaying fallow's paste block: installs the exact scoping this axis rules out. (d) Save baselines at init regardless of wiring: inert for this gate, and suppressive the day the baseline flags are wired. (e) Block on any non-zero fallow exit: false-blocks fresh repos and repos without a detectable base branch.
**Anchored-bet:** [BET]
**Revisit-when:** fallow ships a first-class staged/index scope or an append mode for existing hooks, or fallow audit stops using exit 1 for a fail verdict and exit 2 for errors
**Scope:** cli/lib/install/install-fallow.mts,cli/commands/init.mts,cli/lib/husky/husky-block.mts,cli/lib/husky/gate-policy/fallow-staged.mts,cli/lib/husky/self-host.mts,agents-hooks/**
**Source:** collab · sc-4209
**Evidence-change:** Measured on fallow 3.10.0: fallow hooks install --target git exits 2 over ANY existing .husky/pre-commit, including its own generated one, so in devkit's init order (hook written at step 3, installer at step 8) Target 2's 'fallow's git hook stays as-is' can never take effect; the only result is a relayed --base paste block that false-blocks consumers. Upstream through v3.31.0 has no append mode.
