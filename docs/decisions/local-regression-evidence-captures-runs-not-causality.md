# local-regression-evidence-captures-runs-not-causality

## Target · 2026-08-31 — Local regression evidence captures two runs; reviewers establish causality

**Context:** Story #2408 arose because proving a newly added regression test required temporarily disabling the fix in the caller checkout, then hand-copying output. The proposed command was runner-agnostic over explicit red and green refs. A first implementation grew into a Vitest-4 custom runner that overlaid green tests, inferred hook provenance, and labelled equal named transitions PROVED; research against Bun PRs #40944/#41009 showed that this still could not establish that the claimed fix caused the transition, while excluding bun:test, Jest, pytest, cargo test, and custom Vitest runners.
**Ruling:** devkit prove-regression is a generic evidence-capture command over two explicit commit refs and one exact argv vector. It executes that argv in independent unregistered disposable clones, requires red nonzero and green zero for a CAPTURED result, retains stdout/stderr plus hashes, records immutable SHAs plus cleanup and caller boundary-sample facts, and never calls exit polarity causal proof. An optional standard Vitest JSON report path adds reconciled structured counts and bounded red failure summaries; when requested, a missing or malformed report makes the result inconclusive. Test availability at both refs is the caller responsibility; direct relationship to the ticket and whole-suite sufficiency remain explicit human review claims. Commands are trusted and unsandboxed: inherited repository-local GIT_* overrides are stripped; POSIX process groups or marked descendants are supervised, while Windows safely terminates only the direct helper through its retained process handle. Boundary fingerprints are non-atomic samples, and deliberate ownership evasion or Windows descendants that outlive their parent are outside the portable guarantee. Temporary evidence roots must resolve outside the caller repository.
**Consequences:**
- Positive: The smallest core works with any runner, removes tool-authored caller-checkout mutation, and gives a reviewer exact attributable artifacts instead of handwritten recollection.
- Negative: A nonzero red run can still be a build or setup failure, structured counts are unavailable unless the command emits the optional report, and external services plus intentionally evasive unsandboxed commands remain declared mutable or trusted inputs. Copying each operand's dependency tree also adds local disk and startup cost. This accepts a weaker but honest CAPTURED claim instead of a runner-specific PROVED label; optional adapters may improve the evidence later but cannot silently strengthen its causal meaning.
**Vision-fit:** n/a — internal developer and PR-evidence tooling.
**Researched:** Autonomous report 0a441592-7e95-406a-9071-0f4c1635399e and Story #2408; version audit found continuous absence rather than recurrence (capture d0f246c2 = v0.58.0-19, release v0.59.0, PR base 77308735 = v0.59.0-5, and current main all lacked the command); Bun PR #40944 exact red/fixed outputs and separated ASAN build failure; Bun PR #41009 same-source comparison and semantic-fence tests; Vitest 4 built-in JSON reporter/outputFile documentation; feature-critique RETHINK on PR #530.
**Rejected:** (a) Mandatory custom Vitest runner/reporter and hook probes — rejects other runners/custom runners, couples devkit to advanced transitive APIs, and still cannot prove the green fix caused the transition. (b) Parsing terminal logs for counts or attribution — nested runs already made that unsound on the CI-oracle axis. (c) Calling equal named failed-to-passed cases PROVED — unchanged names do not hold config, setup, external state, or unrelated production changes constant. (d) Automatically overlaying green tests in v1 — the ticket explicitly supplies a test-only red ref; overlay creation is separable convenience, not the missing safety primitive.
**Revisit-when:** Repeated use shows preparing a test-only red ref is the dominant remaining cost, or a runner-neutral report protocol can add structured attribution without narrowing the command.

- 2026-08-31 — PR #530 review hardening: each operand now receives an independent copy-on-write-when-available dependency tree. Contained absolute links are rewritten into the completed snapshot, then all links are validated there and unsafe snapshots are removed, so red cannot mutate the caller store or contaminate green even if the source changes while it is copied. Directory links remain unprivileged junctions on Windows. Windows capture registers only SIGHUP, SIGINT, and SIGBREAK. This removes two accepted portability/mutability risks without changing the explicit-ref, exact-argv, non-causal CAPTURED contract.
- 2026-08-31 — PR #530 final review hardening: evidence schema 3 names the portable observation exactly — the initial and final caller fingerprint samples matched — instead of overclaiming atomic preservation. Operand clones copy their Git objects rather than borrowing the caller store, so concurrent source pruning cannot invalidate an immutable SHA. Windows interruption uses Node's retained direct-child process handle and never passes a PID to `taskkill`: accepting that descendants can outlive their parent is safer than killing an unrelated process after PID reuse. CLI help states both portability boundaries and the already-isolated dependency-copy behavior.
