## 0. Headline

Zero production windowing code is needed to run the deciding experiment. `runCascade` builds each judge's evidence from `sel.files` (`gate-engine/review/run-review.mts:199-205`: `gitCached(cwd, [], files)` → `buildCappedDiffEvidence`), so "chunked review" (file-packed subsets) and "incremental review" (only files changed since attempt k) are both expressible in the bench by passing a `ReviewerSelection` with a files subset into the existing `runReviewerCascade`/`runCascade` seam (`gate-engine/review/eval/reviewers/bench.mts:251-253`). Production pieces (per-file cache grain, overflow chunking, haiku-per-chunk) are each gated by a pre-registered decision rule.

## 2. Design

### 2a. Experiment harness (bench-only; extends `benchmarks-grow-from-telemetry`, `bench-gates-on-flips-not-deltas`, `bench-runs-resume-from-checkpoint`, `benchmark-evidence-append-only`)
- NEW `gate-engine/review/eval/reviewers/skeleton-fixture.mts` (~120 LOC + test): unified diff → `{base, staged}` maps for `materializeFixture` (`bench.mts:76`). base = per-hunk context + `-` lines, staged = context + `+` lines, hunks separated by a sentinel so `git diff --cached` reproduces the identical `±` sequence (line numbers differ; `diffCacheIdentity` drops them, `gate-engine/judge/diff-focus.mts:131-175`). Reuse `splitDiffByFile`/`filePathOf` (`diff-focus.mts:24,32`) + hunk regexes (`:92-95`); devDependency `parse-diff` only if parsing outgrows them (eval is excluded from `dist/`, `zero-consumer-tool-deps` unaffected).
- NEW corpus track, gitignored: `raw/cases-correctness-scale.jsonl` (private frink/owners-web code; only the 78 devkit rows are committable after sanitization — memory: bench banks are not evidence). Row = existing schema (`corpus.mts:40-72`) + `expectItems` = failing lens's `issues_json` "file:line …" string + `reasonPattern` = basename + `provenance:'mined'` + `outcomeEvidence` via `findNextLensOutcome` (`mine-telemetry-lib.mts:140`) + doc-only `diffBytes`, `fileCount`, `prevDiffSha256`, `lens`. Minter: `mine-telemetry.mts --emit-scale-rows` (already gunzips `diffs/<sha>.diff.gz`, `:137-148`; output path `:83`).
- `bench.mts` knobs: `BENCH_CORPUS`, `BENCH_ARM=whole|chunk:<bytes>|incremental:file|incremental:hunk`, `BENCH_CHUNK_MODEL` (bench-only override of the correctness `model` pin); section key (`bench.mts:314`) gains `@arm:<…>` so `progress.mts` salvage never collides.
- Arm logic in `runRow` (`bench.mts:217-258`): `chunk:<B>` packs `sel.files` greedily in diff order by per-file `diffCacheIdentity` length ≤ B (PR-Agent file-packing, never splits a file); one `runReviewerCascade` per pack; merge via `mergeLensOutcomes` (`lens/split.mts:170`) + `mergeLensCaptures` (`:450`); `writer-reader-contracts` ALWAYS whole (brief line 16: cross-root pairs are ONE finding). `incremental:file` = files whose identity differs from `prevDiffSha256`'s archived diff; `incremental:hunk` = only changed hunks staged (measured, not a candidate).
- Scoring: `scoreRow` + `runMatcher`/`kappa` (`gate-engine/review/eval/matcher.mts`) for merged multi-finding outputs; precision proxy = arm findings matching neither gold nor any later production finding on the branch; ≤40-item human disagreement triage.

### 2b. Production algorithms (only if green-lit)
- **P1 per-file cache grain** — extends `ship-gates-converge-not-restart` ruling (1) + `review-gate-in-chain` 2026-07-02 grain; does NOT hit `judge-verdict-cache-scope` Rejected (b) because every CHANGED file's full diff is still shown, only identity-unchanged files replay; reuses `correctness-lens-split-shipped` merge. In `planReviewWork` (`lens/split.mts:308-396`): key = `keyOf(name, diffCacheIdentity(fileSegment), salt|split:<group>|file:<path>)`; un-cached files form the task's selection; `writer-reader-contracts` and cross-file-charter reviewers stay reviewer-grain. Same store (`cache/session.mts:21-26`), FAIL never cached, no dedup needed (unchanged file is not re-judged, so cannot re-flag). Flag `GUARD_REVIEW_CACHE_GRAIN=reviewer|file` (default reviewer). Telemetry: `review_scope` + `cache_grain`, `files_cached`, `files_judged`; `cache_hit` label `review:<name>:file`.
- **P2 overflow chunking** — extends `detect-judge-evidence-only-input`; tension with `ship-gates-converge-not-restart` Rejected (a) mitigated by re-applying the element cap after merge as lens-split does. Trigger only when diff > `EVIDENCE_TOTAL_CAP` 60 000 (`diff-evidence.mts:85`; 13.9% of correctness reviews are blind to part of the diff today). Pack ≤ `GUARD_REVIEW_CHUNK_BYTES` (from E1), one cascade per pack under `mapLimit` (`run-review.mts:469`), `chunk_parts` vector on `review_result` mirroring `lens_parts`; per-pack cache = P1 per-file keys. Flag `GUARD_REVIEW_CHUNK=off|overflow` (default off).
- **P3 haiku-per-chunk** — conflicts with `correctness-reviewer-precision` (sonnet pin for recall); needs a superseding decision note; built only if E1-CH clears.

## 3. Experiment plan — pre-registered in `docs/benchmarks/pre-registration-review-windowing.md` BEFORE any spend; results in `docs/benchmarks/experiments/2026-08-xx-review-windowing/README.md` (existing format)

**E0 finding-location audit ($0, ~1 day).** Over 322 archived fail→fail pairs, classify k+1's lens finding: (a) file identity unchanged k→k+1 (addressable by P1), (b) in changed file/hunk (windowing can't help), (c) file OMITTED/TRUNCATED by `buildCappedDiffEvidence` at k (recomputed deterministically; P2 upside); plus share already verbatim in k's `issues_json` (serial disclosure). Rule: P1 → E2 only if (a) ≥ 30%; P2 → E1 only if (c) ≥ 15% or >60 KB ships ≥ 15% of review-blocked (today 110/499 = 22% of costed correctness ships). If (a) < 30% and serial-disclosure ≥ 40% → stop; the lever is disclosure count (separate decision revisiting Rejected (a)).

**E1 chunk size × model on real diffs.** Stage 1 n=60 gold (5-20 KB 15 · 20-60 KB 30 · >60 KB 15); stage 2 n=120 only if undecided. Arms: W (status quo 4-way, sonnet, `BENCH_CASCADE=off`, concurrency 2) · W′ (re-run = noise floor) · C12 = `chunk:12000` (~300 LOC) sonnet · C40 = `chunk:40000` (~1000 LOC) sonnet · CH = C12 haiku. Co-primary: gold recall; guardrails: unmatched-finding rate, cost/row, secs/row, inconclusive rate; stratified by size and lens. Noise floor = W vs W′ stable net flips (lens-split null ≈ 5/140). MDE: McNemar mid-p < 0.05 on stable flips → ≈ 15 pp at n=60, ≈ 10 pp at n=120; inside floor + CI = UNRESOLVED. Cost (≈ $2 floor + $0.1/KB per ship of 4 judges): W $380 + W′ $380 + C12 ~$600 + C40 ~$450 + CH ~$120 + matcher ~$50 ≈ **$2.0k stage 1** ($1.5k without C40); stage 2 +$2.5k. K=1 probe on 3 rows/bucket first; announce call counts.
Rules: P2 green at size S iff (i) C_S > W on the >60 KB stratum by ≥ floor, mid-p < 0.05; (ii) non-inferior on ≤60 KB strata (no significant one-directional loss, net flips ≤ floor); (iii) unmatched rate ≤ W + noise; (iv) cost/row ≤ 1.5× W on overflow stratum; pick the LARGER passing S. P3 green iff CH non-inferior to C12 on recall AND unmatched ≤ C12 + noise, then still needs a decision note.

**E2 incremental recall loss.** 40 k+1 sides of archived pairs (E0 buckets a/b); arms W(k+1) · IF `incremental:file` · IH `incremental:hunk`; guardrail writer-reader recall. Cost ≈ **$0.8k**. Rule: P1 green iff IF non-inferior to W AND E0 (a) ≥ 30%. IH recorded only (`judge-verdict-cache-scope` Rejected (b), SWE-PRBench Type2/3 predict loss).

Budget: $0 + $1.5-2.0k + $0.8k (+$2.5k optional). Devkit itself spends ~$460/6 wk on judges; payback is in frink-class repos.
